# カード分類・特性・属性メモ v0

## 目的

本実装時に、カードの `classification`、`traits`、`preferredTerrain`、`terrain`、`attributes` を混同しないための基準を置く。

この文書を、カードデータ、カード詳細UI、検索フィルタ、効果処理、コスト評価へ移す時の土台にする。実装に近いデータ形は [コア中央定義フォーマット v0](core-data-definitions-v0.md) を正本にする。

ユーザーメモ由来の分類、特性、得意地形、地形、α特性、必殺技の全体整理は [カードレイヤー設計メモ v0](card-layer-design-memo-v0.md) も参照する。

## 主要レイヤーの役割

| 種別 | 内部名 | 意味 | 持つ場所 | UI表示 | 実効果 |
|---|---|---|---|---|---|
| 分類 | `classification` | そのカードが何の生物群か | カード本体 | 必須 | 分類自体には原則なし |
| 特性 | `traits` | 生態に由来する常時/条件/誘発効果 | カード本体 | 必須 | あり |
| 得意地形 | `preferredTerrain` | 生態に由来する地形適性 | カード本体 | 必須または条件付き | 得意地形ボーナス |
| 地形 | `terrain` | マスごとの盤面効果 | 盤面マス | 必須 | あり |
| 属性 | `attributes` | 攻撃、状態、効果の性質 | 原則として行動コンポーネント | 条件付き | 属性名だけでは発生させない |
| α特性 | `alphaTrait` | α指定時だけ働く特殊効果 | カード本体 | 条件付き | あり |
| 必殺技 | `ultimate` | 指定ターン後に使える特殊行動 | カード本体 | 必須または条件付き | あり |

例えば `水棲` は特性、`海` は地形、`得意地形=海` はカード本体の地形適性、`電気` は属性候補であり、同じ階層に混ぜない。

## 基本ルール

| ルール | 内容 |
|---|---|
| 分類は原則1つ | 図鑑、分類統一、分類参照効果の軸にする |
| 分類そのものに共通効果を持たせない | 鳥類だから必ず飛行、魚類だから必ず水棲にはしない |
| 特性は1〜3個 | 実際のルール効果、地形依存、体構造、行動傾向を表す |
| 得意地形は分類や特性から自動生成しない | 例外生物や特殊カードを扱うため、カード本体へ明示する |
| 地形効果は地形側に置く | 海、砂漠、火山、極地などの共通ペナルティはマス側のルールにする |
| 特定行動だけの効果は特性にしない | 後衛時だけ強い攻撃などは行動側に置く |
| 属性は主に行動に付ける | カードの種族タグではなく、その攻撃や状態が何性質かを表す |
| 属性名だけで相性補正を隠さない | 弱点、耐性、追加効果は `effectElements`、`STATUS_EFFECTS`、条件式で明示する |
| UIでは分類/特性を優先する | 属性は属性参照カード、耐性、弱点、変換が実装された段階で表示する |
| ユーザー向け用語は `α特性` を優先する | ユーザーメモ上の「αスキル」は、既存UIでは `α特性` として扱う |
| 必殺技は通常行動の代わりに使う | 指定ターン後、位置条件に縛られない強行動として扱う |

## 分類

分類は「生物としてのまとまり」。世界観、図鑑、分類統一デッキ、分類参照のα特性で使う。

| ID | 表示名 | 主な設計傾向 | 付きやすい特性 |
|---|---|---|---|
| `fish` | 魚類 | 海地形、高HP、シンプルな行動、捕食 | 水棲、捕食、発電、群体 |
| `amphibian` | 両生類 | 回復、復活、毒、バフ | 水棲、毒性、再生、擬態 |
| `reptile` | 爬虫類 | 強攻撃、高HP、古代、大型、捕食。恐竜系と翼竜系も含む | 水棲、古代、巨大、飛行、捕食 |
| `bird` | 鳥類 | 高AG、奇襲、後衛到達、低HP | 飛行、疾走、擬態、捕食 |
| `mammal` | 哺乳類 | 標準ステータス、地形適応、群れ | 疾走、群れ、捕食 |
| `crustacean` | 甲殻類 | 装甲、前衛維持、反撃 | 甲殻、水棲、毒耐性 |
| `insect` | 昆虫類 | 低コスト、群体、毒性、擬態、飛行 | 群体、飛行、毒性、擬態 |
| `plant` | 植物 | AT低め。支援、妨害多め | 果実、毒性、擬態 |
| `fungi` | 菌類 | 回復、拡散、寄生、毒性 | 菌糸、寄生、毒性、群体 |
| `dragon` | 竜類 | 高コスト、高AT、属性攻撃、範囲攻撃、α向き | 飛行、古代、巨大、甲殻 |
| `inorganicLife` | 無機生命 | 高HPまたは防御特性で硬さを出す。低AG寄りも候補 | 結晶、発電、毒耐性、装甲 |
| `phantomBeast` | 幻獣 | ステータス高め。尖った性能 | 古代、巨大、発電、擬態 |
| `mollusk` | 軟体類 | アンモナイト、イカ、タコ、貝類など。水棲、擬態、装甲、妨害と相性がよい | 水棲、擬態、甲殻、毒性 |

廃止/統合:

| 対象 | 扱い |
|---|---|
| `dinosaur` | 独立分類にしない。恐竜系は `reptile` + 高ステータス/`ancient`/`giant` で特徴づける |
| `pterosaur` | 独立分類にしない。翼竜系は `reptile` + `flying` で特徴づける |
| `crystalLife` | `inorganicLife` へ統合する。`結晶` は分類ではなく特性またはカード群テーマとして扱う |

決定: `insect` と `crustacean` は独立分類を正とする。甲殻類は硬さ/反撃、昆虫類は群体/毒/飛行/擬態で差を出す。

注意: 魚類の群れ表現は現プロトタイプでは `swarm` に寄せている。魚類専用の `schooling` を正式特性にする場合は、`TRAITS` へ追加してから参照する。

## 特性

特性は「カードが持つ生態由来の実効果」。カード詳細で説明を出し、検索、採点、戦闘処理でも参照する。

| ID | 表示名 | 主な機能 | 典型的な弱点/対策 |
|---|---|---|---|
| `flying` | 飛行 | 地形効果無視、地形ペナルティ回避 | 対飛行妨害、低HP設計 |
| `aquatic` | 水棲 | 海で高性能、海以外で弱体 | 地形依存、海を使えない構築 |
| `dash` | 疾走 | 高AG、先手、奇襲 | 装甲、回復、AG弱体 |
| `predation` | 捕食 | 低HP狙い、撃破時強化 | 防御/回復で確定数をずらす |
| `mimicry` | 擬態 | サーチ回避、対象逸らし | 範囲攻撃、ランダム対象 |
| `poisonous` | 毒性 | 毒、継続ダメージ、回復阻害 | 毒耐性、短期決戦 |
| `poisonResist` | 毒耐性 | 毒/継続ダメージへの回答 | 毒以外には価値が落ちる |
| `swarm` | 群体 | 複数対象支援、同分類/同特性参照 | 範囲攻撃、撃破時効果 |
| `pack` | 群れ | 同列支援、連携、前衛展開 | 範囲攻撃、支援役狙い |
| `mycelium` | 菌糸 | 回復、広域支援、継続効果 | 回復封じ、後衛圧 |
| `parasitic` | 寄生 | 弱体、毒、撃破時誘発 | 毒耐性、打ち消し |
| `ancient` | 古代 | 高コスト、強い必殺技、α向き。妨害耐性も候補 | 初動の遅さ、短期決戦 |
| `giant` | 巨大 | 高HP、前衛制圧、α適性 | 低AG、貫通、割合/サーチ |
| `carapace` | 甲殻 | 装甲、ダメージカット、反撃 | 貫通、防御低下、回復封じ |
| `crystal` | 結晶 | バリア、反射、地形連動 | バリア貫通、防御低下 |
| `electric` | 発電 | AG操作、麻痺、連鎖攻撃 | 発動前撃破、AG耐性 |

ユーザーメモから追加候補にする特性:

| ID案 | 表示名 | 主な機能 | 注意 |
|---|---|---|---|
| `resistance:*` | 各種耐性 | 特定状態異常を無効化、または影響軽減 | 毒耐性、デバフ耐性、即死耐性などを必要に応じて分ける |
| `armored` | 装甲 | 常時ダメージカット状態 | 効果要素の `armor` とは別名にする候補 |
| `fruit` | 果実 | 毎ターン周囲の味方を小回復 | 植物系支援の軸 |
| `spore` | 胞子 | 自身を攻撃した敵を毒状態にする | 属性候補の `spore` と同名にする場合は名前空間を分ける |

注意: `aquatic` のユーザーメモ案は「海以外でAT/AG x0.8」。現プロトタイプ文言にはHPも含むため、本実装前にAT/AGのみへ寄せるか確認する。

注意: `ancient` の妨害耐性は議論予定。採用する場合は、毒耐性のような個別耐性にするか、AG低下、行動阻害、必殺技妨害への軽減にするかを分けて決める。

特性は、カード本体の `traits` に置く。特性が実際にどの効果要素へつながるかは `effectElements` に明示する。

```js
const card = {
  id: "thunderEel",
  classification: "fish",
  traits: ["aquatic", "electric"],
};
```

## 得意地形と地形

得意地形はカード本体、地形は盤面マスに置く。どちらも分類や特性から自動生成しない。

得意地形の基本案:

| 条件 | 効果 |
|---|---|
| カードが得意地形上にいる | AT/AG x1.2 |

本実装候補の地形:

| ID案 | 表示名 | 効果方針 |
|---|---|---|
| `plain` | 平地 | デフォルト。得意分類なし |
| `forest` | 森 | 森林とジャングルは統合候補 |
| `rockyMountain` | 岩山 | 岩場、崖、山岳系の配置コンボ用 |
| `sea` | 海 | 得意でないカードはAG x0.5 |
| `desert` | 砂漠 | 得意でないカードはAG x0.8 |
| `volcano` | 火山 | 得意でないカードは毎ターンダメージ |
| `polar` | 極地 | 得意でないカードは毎ターンAT/AG低下 |

現プロトタイプの `高地` は `岩山`、`活性巣` と `殻壁` は特殊地形またはカード生成地形として再整理する候補。

## 属性

属性は「攻撃や状態の性質」。本実装では最初から大きな相性表を作らず、属性参照が必要になった時だけ中央定義する。

推奨する初期方針:

- カード本体へ単一の属性を必須で持たせない。
- 属性はまず `ACTION_METADATA.components[].attributes` に置く。
- 耐性や弱点を入れる場合は、カード本体の `resistAttributes`、`weakAttributes` を任意項目として追加する。
- 属性による追加効果は、必ず `effectElements` や `STATUS_EFFECTS` にも分解する。
- 「電気属性だからAGが下がる」のような隠し処理にしない。

候補:

| ID | 表示名 | 主な接続先 | 使う場面 |
|---|---|---|---|
| `physical` | 物理 | 単体攻撃、範囲攻撃、反撃 | 通常の接触、突進、噛みつき |
| `electric` | 電気 | AG弱体、麻痺、連鎖攻撃 | 発電、生体電流、放電 |
| `acid` | 酸 | 防御低下、回復封じ、装甲対策 | 腐蝕、酸噴霧、溶解 |
| `poison` | 毒 | 毒、接触毒、回復阻害 | 毒針、毒胞子、毒液 |
| `heat` | 熱 | 範囲攻撃、燃焼候補 | 火山熱線、発熱、燃焼 |
| `spore` | 胞子 | 毒、寄生、回復/支援 | 菌糸、胞子雲、寄生 |
| `crystalEnergy` | 結晶 | バリア、反射、貫通候補 | 無機生命/結晶系の反射/共鳴 |

例:

```js
const ATTRIBUTES = {
  electric: {
    name: "電気",
    shortText: "発電系の攻撃やAG操作に使う属性。",
    relatedTraits: ["electric"],
    relatedEffectElements: ["agDebuff", "agBuff"],
    relatedStatusEffects: ["paralysis"],
  },
  acid: {
    name: "酸",
    shortText: "装甲や回復を崩す腐蝕系の属性。",
    relatedTraits: ["poisonous", "parasitic"],
    relatedEffectElements: ["defenseDown", "healBlock", "barrierPierce"],
  },
};
```

行動側:

```js
const ACTION_METADATA = {
  highVoltageDischarge: {
    name: "強放電",
    text: "敵味方前衛へダメージを与え、AGを下げる。",
    components: [
      {
        effectElements: ["areaAttack", "agDebuff"],
        targetPattern: "frontRankUnits",
        formula: "atDamageAndAgMinus10",
        attributes: ["electric"],
      },
    ],
  },
};
```

`frontRankUnits` は敵味方巻き込み攻撃を入れる時の対象パターン候補。既存の敵前衛攻撃だけなら `frontRankEnemies` を使う。

カード側へ属性を置くのは、耐性、弱点、属性強化、属性参照のα特性が実装された後でよい。

```js
const card = {
  id: "acidCoral",
  classification: "inorganicLife",
  traits: ["aquatic", "poisonous", "crystal"],
  resistAttributes: ["acid"],
};
```

## 判断フロー

カード案を作る時は、以下の順で決める。

1. 生物として何かを決める: `classification`
2. 生態として常時/条件/誘発で働くものを決める: `traits`
3. 地形適性を決める: `preferredTerrain`
4. 前衛/中衛/後衛で何をするかを決める: `ACTION_METADATA`
5. その行動の効果要素を分解する: `effectElements`
6. 効果が属性参照を必要とするなら付ける: `attributes`
7. α指定時だけの差分を決める: `alphaTrait`
8. 指定ターン後の強行動を決める: `ultimate`
9. 耐性/弱点/属性強化が必要な時だけカード本体に属性関連項目を追加する

例:

| カード | 分類 | 特性 | 行動属性 |
|---|---|---|---|
| 電気ウナギ型 | 魚類 | 水棲 / 発電 | 電気 |
| アシッドコーラル | 無機生命 | 水棲 / 毒性 / 結晶 | 酸 / 毒 |
| ボルカノドレイク | 竜類 | 飛行 / 巨大 / 古代 | 熱 |
| スポアコロニー | 菌類 | 菌糸 / 毒性 | 胞子 / 毒 |
| メガロドン | 魚類 | 水棲 / 捕食 / 巨大 | 物理 |

## 実装優先度

| 段階 | 対応 |
|---|---|
| v0 | `classification` と `traits` を必須化。属性は文書予約 |
| v1 | `ATTRIBUTES` を中央定義し、行動コンポーネントへ `attributes` を任意追加 |
| v2 | 属性アイコン、属性フィルタ、属性参照のα特性を追加 |
| v3 | 必要になった場合だけ耐性/弱点/属性変換を追加 |

属性相性表は急いで入れない。相性表を先に作ると、分類デッキ、特性デッキ、地形デッキに加えて属性デッキまで同時に管理する必要が出て、初期カードプールの評価がぼやける。

## 実装前チェック

- 分類、特性、属性が同じ意味で重複していないか。
- 分類タグだけで自動的に強くなっていないか。
- 特性説明と戦闘処理が一致しているか。
- 属性名だけの隠し補正がないか。
- 属性参照が `effectElements`、`STATUS_EFFECTS`、`TARGET_PATTERNS` へ展開できるか。
- UIでプレイヤーが見る情報と、内部だけで持つ設計意図が分かれているか。
