# カードレイヤー設計メモ v0

作成日: 2026-08-16

ユーザーの分類、特性、地形メモを、本実装時に参照しやすい形へ整理したもの。

## 中心方針

カードの生物分類、常在効果、地形適性、盤面地形、行動属性は別レイヤーとして扱う。

例:

```js
const card = {
  classification: "fish",
  traits: ["aquatic"],
  preferredTerrain: ["sea"],
};
```

`分類=魚類` だから自動的に水棲になる、という扱いにはしない。魚類でも水棲でないカード、爬虫類でも水棲を持つカード、海が得意だが水棲ではないカードを許容する。

## レイヤー

| レイヤー | 内部名 | 持つ場所 | 役割 |
|---|---|---|---|
| 分類 | `classification` | カード本体 | モデル生物やモチーフの大分類。分類統一デッキ、図鑑、分類参照効果の軸 |
| 特性 | `traits` | カード本体 | モデル生物やモチーフに由来する常在、条件、誘発効果 |
| 得意地形 | `preferredTerrain` | カード本体 | 地形との相性。配置と地形コンボの軸 |
| 地形 | `terrain` | 盤面マス | マスごとの効果。配置判断と盤面構築の軸 |
| 属性 | `attributes` | 原則として行動コンポーネント | 攻撃、状態、効果の性質。分類や特性とは分ける |
| α特性 | `alphaTrait` | カード本体 | αに指定された場合のみ働く追加効果 |
| 必殺技 | `ultimate` | カード本体 | 指定ターン後に通常行動の代わりに使える強行動 |

## カード分類

分類はモデル生物やモチーフの生態に準拠して設定する。分類そのものを参照するバフや行動を採用することで、分類統一型のコンセプトデッキにも利用する。

| ID案 | 表示名 | 設計傾向 |
|---|---|---|
| `fish` | 魚類 | 水棲寄り。シンプルな行動多め。HP高め |
| `amphibian` | 両生類 | 回復、復活、毒、バフ持ち多め |
| `reptile` | 爬虫類 | 強攻撃持ち多め。恐竜系は高ステータス、翼竜系は飛行特性で特徴づける |
| `bird` | 鳥類 | 飛行寄り。HP低め。サーチ攻撃、中後衛攻撃多め |
| `mammal` | 哺乳類 | 多様な行動を持つバランス型 |
| `crustacean` | 甲殻類 | ステータス控えめ。特性や行動がトリッキー |
| `insect` | 昆虫類 | 低コスト、群体、毒性、擬態、飛行などで甲殻類とは別の軽量分類にする |
| `plant` | 植物 | AT低め。支援、妨害多め |
| `fungi` | 菌類 | AT低め。支援、妨害、毒多め |
| `dragon` | 竜類 | ステータス高め。属性攻撃多め |
| `inorganicLife` | 無機生命 | 高HPまたは防御特性で硬さを出す。低AG寄りも候補 |
| `phantomBeast` | 幻獣 | ステータス高め。尖った性能 |
| `mollusk` | 軟体類 | アンモナイト、イカ、タコ、貝類など。水棲、擬態、装甲、妨害と相性がよい |

分類は傾向であり、ルール効果ではない。例えば `bird` は飛行を持ちやすいが、飛べない鳥類カードも作れる。

廃止する独立分類:

| 旧候補 | 扱い |
|---|---|
| 恐竜 | 独立分類にはしない。`爬虫類` に含め、高ステータス傾向、`古代`、`巨大`、`捕食` などで特徴づける |
| 翼竜 | 独立分類にはしない。`爬虫類` に含め、`飛行` 特性と低HP/高AG寄りのステータスで特徴づける |

統合扱いする分類:

| ID | 表示名 | 判断 |
|---|---|---|
| `crystalLife` | 結晶生命 | 独立分類ではなく `無機生命` のカード群、または特性 `結晶` として扱う候補 |

名称と分類階層の要判断:

| 対象 | 指摘 | 推奨 |
|---|---|---|
| 爬虫類 / 恐竜 / 翼竜 | 恐竜、翼竜は廃止し、爬虫類に含める方針 | 恐竜系は高ステータス、翼竜系は `飛行`、古代種は `古代` で差を出す |
| 竜類 | `ドラゴン` も分かりやすいが、他の分類名と並べると外来語感が強い | 分類表示名は `竜類` を正とする。カード名や図鑑文ではドラゴン表現を使ってよい |
| 無機生命 | 結晶生命の代替分類。硬さをどう出すかが要判断 | 高HPで硬くする案と、防御特性や `結晶` で硬くする案を比較する。分類自体に防御効果は持たせない |
| 幻獣 | ファンタジー寄りに見えやすい | 図鑑テキストや効果を生態系SF寄りにし、魔法的な万能分類にしない |
| 昆虫類 / 甲殻類 | 生物分類としてもカード性能傾向としても違う | `昆虫類` と `甲殻類` は独立分類を正とする。甲殻類は硬さ/反撃、昆虫類は群体/毒/飛行/擬態で差を出す |
| 軟体類 | アンモナイト系を魚類へ入れると違和感が強い | 正規分類として追加する。水棲、擬態、装甲、妨害、絡め取り系の行動で個性を出す |

## 特性

特性はカードが持つ常在、条件付き、誘発型の特殊能力。モデル生物やモチーフに準拠し、カード個性を強く出す。

| ID案 | 表示名 | 効果方針 |
|---|---|---|
| `aquatic` | 水棲 | 海以外の地形ではAT/AG x0.8。海に特化した生物を表現する特例 |
| `flying` | 飛行 | 地形効果を受けない |
| `mimicry` | 擬態 | 特定地形にいる間、サーチ攻撃の対象にならない |
| `ancient` | 古代 | 高コスト、強い必殺技、α向き。妨害系への耐性も候補 |
| `resistance:*` | 各種耐性 | 特定状態異常を無効化、または影響軽減。毒、デバフ、即死耐性など |
| `armored` | 装甲 | 常時ダメージカット状態 |
| `fruit` | 果実 | 毎ターン周囲の味方を小回復 |
| `spore` | 胞子 | 自身を攻撃した敵を毒状態にする |

補足:

- `aquatic` の弱体対象は、このメモではAT/AGのみとする。現プロトタイプ文言にはHPも含む箇所があるため、本実装前にどちらへ寄せるか決める。
- `spore` は属性候補としても使える。特性IDと属性IDで同名にする場合は、UIと処理で名前空間を明確に分ける。
- `armored` は特性、`armor` は状態効果または効果要素として分けると扱いやすい。
- `ancient` の妨害耐性は議論予定。採用する場合も、毒耐性のような個別耐性にするか、AG低下、行動阻害、必殺技妨害への軽減にするかを分けて決める。

## 得意地形

得意地形はカード本体の地形適性として持たせる。

基本案:

| 条件 | 効果 |
|---|---|
| カードが得意地形上にいる | AT/AG x1.2 |

得意地形は、分類や特性とは別に管理する。例えば `classification=fish`、`traits=["aquatic"]`、`preferredTerrain=["sea"]` は同時に持てるが、それぞれの参照先と効果は分ける。

## 地形

地形は各マスに設定される特殊効果。配置そのものが重要なゲームであるため、盤面構築、配置判断、デッキコンボに関与する重要システムとする。

| ID案 | 表示名 | 効果方針 |
|---|---|---|
| `plain` | 平地 | デフォルト。得意分類なし |
| `forest` | 森 | 森林とジャングルを生態学的には分けられるが、ゲーム上の複雑化を避けるため統合も検討 |
| `rockyMountain` | 岩山 | 岩場、崖、山岳系の配置コンボ用 |
| `sea` | 海 | 得意でないカードはAG x0.5 |
| `desert` | 砂漠 | 得意でないカードはAG x0.8 |
| `volcano` | 火山 | 得意でないカードは毎ターンダメージ |
| `polar` | 極地 | 得意でないカードは毎ターンAT/AG低下 |

現プロトタイプとの差分:

| プロトタイプ | 本実装候補 |
|---|---|
| `高地` | `岩山` へ寄せる候補 |
| `活性巣` | 生物由来の特殊地形、またはカード生成地形として再整理 |
| `殻壁` | 甲殻/防御系の特殊地形、またはカード生成地形として再整理 |

## α特性

ユーザーメモ上の「αスキル」は、既存UI方針では `α特性` と呼ぶ。

α特性はカードがαに指定された場合のみ発動する特殊効果。通常の特性や行動に追加効果が発生するイメージとし、内容はカードごとに多様にする。

α指定そのものを、デッキ構築と配置上の重要な選択にする。

## 必殺技

必殺技は、指定ターン数が経過すると使用可能になる特殊行動。

基本方針:

- マスや通常の行動位置条件に依存せず使用可能。
- 発動時は通常行動の代わりに実行する。
- 使用可能になるまでのターン制限をコストとして、通常行動より強力な効果を持たせる。

## データモデルへの反映

最小カード形:

```js
const card = {
  id: "exampleCard",
  name: "カード名",
  classification: "fish",
  traits: ["aquatic"],
  preferredTerrain: ["sea"],
  frontAction: "frontActionId",
  middleAction: "middleActionId",
  rearAction: "rearActionId",
  alphaTrait: "alphaTraitId",
  ultimate: "ultimateId",
};
```

行動属性:

```js
const ACTION_METADATA = {
  exampleAction: {
    name: "放電",
    components: [
      {
        effectElements: ["singleAttack", "agDebuff"],
        targetPattern: "frontEnemy",
        formula: "atDamageAndAgMinus10",
        attributes: ["electric"],
      },
    ],
  },
};
```

カード本体に属性を必須で持たせる必要はない。属性はまず行動コンポーネントの性質として扱い、耐性、弱点、属性参照効果が必要になった段階でカード本体へ `resistAttributes` や `weakAttributes` を追加する。
