# ゲーム設計指針 v0

作成日: 2026-08-12

## 目的

この文書は、仕様を増やす時、カードを設計する時、バランスを調整する時に参照する上位の判断基準である。

個別仕様の正本ではない。コアルールは [α戦コアルール プロトタイプv0](./core-rules-prototype-v0.md)、カード表示と内部設計は [カード設計スキーマ v0](./card-design-schema-v0.md)、勝ち筋の分類は [勝ち筋構築セオリー v0](./win-plan-construction-theory-v0.md)、検証指標は [デッキ検証指標 v0](./deck-validation-metrics-v0.md) を優先する。

この文書の役割は、迷った時に「このゲームではどちらを選ぶべきか」を決めることである。

## このゲームで目指す体験

このゲームの中核は、戦闘中の細かい操作ではなく、構築、配置、検証、再構築のループにある。

```text
仮説を立てる
  -> デッキと配置を組む
  -> 自動戦闘を見る
  -> 勝った理由/負けた理由を読む
  -> 次の仮説で組み替える
```

理想のプレイヤー体験は、次の状態である。

| 体験 | 内容 |
|---|---|
| 組む前 | カード、地形、α指定から「この勝ち筋はいけそう」と考えられる |
| 戦闘中 | 何が起きているかを追える。重要な行動、対象、状態変化が見える |
| 勝利時 | 自分の構築意図が戦闘ログ上で確認できる |
| 敗北時 | 相手の勝ち筋、こちらの弱点、次に試す対策を推測できる |
| 調整時 | 勝率だけでなく、決着ターン、α露出、主軸行動回数などから原因を分解できる |

短く言えば、**見れば納得でき、組めば発見があり、負ければ次の仮説が立つゲーム**を目指す。

## 中核となる面白さ

### 1. 勝ち筋を組む面白さ

このゲームでの勝ち筋は「相手の何をどう崩して勝つか」である。

一点突破、盤面制圧、α直接突破、エース遂行、継続ダメージ耐久、妨害制圧、反撃/受け崩しなどは、同じ階層の勝ち筋として扱う。分類統一、特性統一、地形、必殺技短縮、α支援などは、勝ち筋そのものではなく勝ち筋を成立させる構築エンジンである。

プレイヤーに感じてほしいのは「強いカードを入れた」ではなく、「この崩し方を成立させた」である。

### 2. 配置と対象条件の読み合い

3x3盤面、前衛/中衛/後衛、左列/中央列/右列、前進、α保護、α露出は、このゲームの主な読み合いの土台である。

カード効果は、単に数値が高いだけでなく、どの位置から、どの対象へ、どのタイミングで届くかが重要でなければならない。配置が変わっても同じように強いカードばかりになると、盤面ゲームである意味が薄れる。

### 3. ログから学ぶ面白さ

自動戦闘では、プレイヤーは結果だけを受け取ると納得しにくい。重要なのは、結果へ至る過程を読めることである。

リプレイ、戦闘ログ、状態チップ、対象マス図は、演出ではなく学習装置である。勝率表示だけでは、なぜ勝ったか、なぜ負けたか、何を変えればよいかが分からない。

### 4. 制約の中で最適化する面白さ

30コスト、盤面9マス、αコスト、配置制約、地形コスト、レアリティ、将来の同名制限や枚数制限は、プレイヤーの創造性を縛るためではなく、選択を意味あるものにするためにある。

強い候補を全部入れられないから、デッキに個性が出る。支援を入れると火力が減り、守りを厚くするとα到達が遅れ、速攻に寄せると長期戦に弱くなる。このような手触りを重視する。

## 設計原則

### 原則1: すべての強さにはリスク、条件、代償を置く

強い効果そのものは許容する。ただし、強い効果には次のいずれかが必要である。

| 代償の種類 | 例 |
|---|---|
| コスト | 高コスト、αコスト増、地形コスト |
| 位置条件 | 前衛でしか使えない、後衛に置くには足場が必要 |
| 対象条件 | 露出αのみ、低HPのみ、同列のみ |
| 時間条件 | 必殺技必要ターン、準備ターン、持続切れ |
| 構築条件 | 分類統一、特性統一、地形一致、支援役の採用 |
| 対策余地 | 貫通、防御低下、回復封じ、AG操作、配置変更で崩せる |

「高火力、高耐久、高速、広範囲、低コスト、対策困難」が同時に成立するカードは作らない。

### 原則2: 選択は状況依存にする

よい選択肢とは、常に正解ではなく、状況によって価値が変わる選択肢である。

| よい選択 | 悪い選択 |
|---|---|
| 速いが脆い | 速くて硬くて火力も高い |
| 後衛に届くが前線処理が遅い | どこにでも十分な火力が出る |
| αを守れるが盤面制圧されやすい | 守りながら相手全体も倒せる |
| 地形一致で強い | 地形に関係なく最強 |
| 必殺技が強いが到達まで守る必要がある | 序盤から終盤まで常に強い |

カード、地形、α指定、配置のどれにも、選ぶ理由と選ばない理由を用意する。

### 原則3: 勝ち筋は強くてよいが、対策不能にしない

構築の噛み合いで強くなることは、このゲームの報酬である。シナジーそのものに過剰なコスト課税をしない。

ただし、強い勝ち筋には現実的な回答が必要である。

| 勝ち筋 | 主な回答 |
|---|---|
| 一点突破 | 装甲、回復、対象逸らし、先制妨害、低HP保護 |
| 盤面制圧 | 主砲撃破、範囲軽減、分散配置、回復封じへの回答 |
| α直接突破 | α保護、壁再構築、貫通軽減、露出後の先制 |
| エース遂行 | エース狙い、支援役撃破、AG低下、防御低下 |
| 継続ダメージ耐久 | 回復封じ対策、毒解除、速攻、必殺技による突破 |
| 妨害制圧 | 妨害役撃破、耐性、低AG構築、即時火力 |
| 反撃/受け崩し | 非接触攻撃、継続ダメージ、防御無視、後衛狙い |

回答札を入れても結果がほぼ変わらない場合は、コストではなく、効果要素、対象、持続、必要ターン、AG、配置条件を見直す。

### 原則4: 複雑さはカード本文ではなく相互作用へ寄せる

深さは必要だが、読みづらさは不要である。

カード1枚の説明文で難しくするより、単純な効果同士が配置、対象、行動順、地形、α指定で組み合わさって深くなる状態を目指す。

| 優先 | 避ける |
|---|---|
| 短い効果 + 明確な対象 + 分かりやすい条件 | 長文効果 + 例外処理 + 不明瞭な対象 |
| 位置ごとに役割が変わる | どの位置でも同じ万能効果 |
| 2枚から3枚の噛み合い | 5枚以上そろわないと意味が分からないコンボ |
| ログで追える状態変化 | 内部でだけ効いている不可視補正 |

カード効果を追加する時は「この効果は対象マス図、ログ、状態チップで簡潔に見せられるか」を確認する。

### 原則5: UIは答えではなく、判断材料を見せる

プレイヤーに勝ち筋を押し付けすぎると、発見の楽しさが弱くなる。

UIで明示するものは、ルールとして必要な情報である。カード設計者が意図した勝ち筋、危険な組み合わせ、想定対策は内部情報に留める。

| UIで見せる | 内部に留める |
|---|---|
| HP/AT/AG、コスト、αコスト | 想定勝ち筋 |
| 前衛/中衛/後衛行動 | 想定コンボ |
| 対象マス図、効果式、状態チップ | 危険な組み合わせ |
| 分類、特性、地形適性 | 採点内訳 |
| 役割タグは攻撃/防御/支援など粗く表示 | 詳細なデッキタイプ分類 |

「何ができるか」は見せる。「どう勝つべきか」はプレイヤーに発見させる。

### 原則6: 結果の納得感を数理的正しさより優先する

ルールが数学的に公平でも、プレイヤーが不公平に感じることはある。

このゲームでは、自動戦闘、同速処理、対象選択、乱数、ドロー、状態異常などが納得感を損ないやすい。実装上は正しくても、ログで理由を追えないなら問題である。

特に注意するもの:

| 要素 | リスク | 方針 |
|---|---|---|
| 同速処理 | なぜ先に動いたか分からない | コスト、レアリティ、盤面優先など決定規則を明示する |
| 対象選択 | 狙ってほしい敵を攻撃しない | 対象条件と優先順をカード詳細で示す |
| 軽い乱数 | 負けが理不尽に見える | 乱数幅、発生理由、再戦時の揺れを明確にする |
| 回復/装甲 | 何点得したか見えにくい | 実回復量、軽減量、無効化量をログに出す |
| α保護 | なぜαへ届かなかったか分からない | 保護状態と軽減理由を表示する |

将来乱数を入れる場合も、構築と配置の判断が主であり、乱数は環境検証や展開の揺らぎを作る補助に留める。

### 原則7: テンポは「考える時間」と「見る時間」を分ける

このゲームは自動戦闘なので、操作の忙しさではなく、構築前後の思考に時間を使わせる。

戦闘は5から7ターン決着を標準にする。リプレイは、初見では理解できる速度、再確認では早送りできる速度にする。長い膠着は、意図した耐久勝ち筋であっても、ログ上の変化がなければ退屈になる。

| 場面 | 方針 |
|---|---|
| 構築 | 比較、検索、配置変更、α指定を素早く試せる |
| 戦闘 | 重要行動を追える。演出は情報を隠さない |
| 検証 | 100戦結果、代表戦、指標を行き来できる |
| 再調整 | 前回の失敗理由からすぐカード/配置を変えられる |

### 原則8: 世界観は判断を助ける時に強く使う

世界観は「異世界生態系SF」とする。ただし、主要UIは汎用的なゲーム用語を優先する。

分類、特性、地形、図鑑テキスト、カード名は、世界観を出しながら戦略の匂わせにも使う。例えば「飛行」は後衛到達や回避、「甲殻」は装甲、「菌糸」は継続ダメージや回復阻害、「水棲」は海地形との関係を連想させる。

フレーバーは、ルール理解を曇らせてはいけない。世界観語が格好よくても、プレイヤーが効果を誤読するならUIの主要語には使わない。

### 原則9: 初心者には入口を、上級者には分解余地を用意する

初級者、中級者、上級者で面白さの階層を分ける。

| 層 | プレイヤーが学ぶこと | 必要な支援 |
|---|---|---|
| 初級 | αを守る/倒す、前衛が崩れるとαが露出する | 教材デッキ、対象マス図、短いログ |
| 中級 | 一点突破、盤面制圧、エース遂行などの勝ち筋 | 役割タグ、代表リプレイ、勝ち筋別プリセット |
| 上級 | AG、対象条件、地形、必殺技短縮、対策札の差し替え | 検証指標、詳細ログ、カード検索メタデータ |

初心者向けの簡略化は、上級者の深さを消すことではない。上級者向けの深さは、初心者の画面を重くすることでもない。

### 原則10: 検証は勝率だけで判断しない

勝率は重要だが、勝率だけでは問題の原因が分からない。

見るべき指標:

| 指標 | 何を見るか |
|---|---|
| 平均決着ターン | 速すぎる非ゲーム化、遅すぎる膠着 |
| α露出ターン | 壁処理とα到達の速度 |
| α撃破ターン | 勝利条件への到達速度 |
| 主軸行動回数 | 勝ち筋の中核が機能したか |
| 主軸生存ターン | エース保護、主砲保護、支援保護の成立 |
| 有効ダメージ | 撃破、α露出、行動減少に変換された量 |
| 延命量 | 回復/装甲が単なる遅延か、勝ち筋に変換されたか |
| 状態付与回数 | 毒、回復封じ、防御低下、AG操作の機能 |
| 対策後の勝率変化 | 回答札や配置変更で結果が動くか |

調整では、強いカードを弱くする前に「なぜ強いのか」を分解する。

## 仕様判断の優先順位

仕様や調整で迷った時は、次の順に優先する。

1. 勝った理由、負けた理由が分かること。
2. 構築と配置の選択が勝敗に影響すること。
3. 強い勝ち筋に現実的な対策があること。
4. 1戦のテンポが標準範囲に収まること。
5. カード効果が読みやすく、ログで追えること。
6. 世界観が魅力を足し、ルール理解を邪魔しないこと。
7. コンテンツ量より、少ないカードで多様な勝ち筋が出ること。

新しい仕様がこの優先順位の上位を悪化させる場合、下位の魅力があっても採用を保留する。

## カード設計指針

### カード1枚に求めること

カードは、単体で完結した強さではなく、構築内の役割を持つべきである。

設計時に必ず確認する。

| 確認項目 | 問い |
|---|---|
| 役割 | このカードは攻撃、防御、支援、妨害、回復のどれに主に寄与するか |
| 位置 | 前衛/中衛/後衛のどこに置きたいカードか |
| 対象 | どの敵/味方へ届くカードか |
| 勝ち筋 | どの勝ち筋の部品になるか |
| 代償 | 強い場合、何を失っているか |
| 対策 | 相手は何で咎められるか |
| 表示 | 対象マス図、効果式、ログで分かるか |

### よいカードの条件

| 条件 | 説明 |
|---|---|
| 居場所がある | 特定の勝ち筋、地形、分類、特性、配置で採用理由がある |
| 入れ得ではない | どのデッキにも入る汎用正解にならない |
| 対策できる | 苦手な対象、速度、地形、勝ち筋がある |
| 使うと分かる | 戦闘ログで仕事が確認できる |
| 捨てる理由もある | コスト、位置、対象、テンポなどで不採用理由がある |

### 避けるカード

| パターン | 問題 |
|---|---|
| 万能高効率 | デッキ構築の選択を減らす |
| 長文例外処理 | 読む負荷が高く、ログでも追いにくい |
| 対策不能な防御 | 膠着か一方的な勝利になりやすい |
| 低コストの汎用支援 | ほぼ全デッキに入り、環境を固定する |
| 高AGサーチ高火力 | 相手の行動前にゲームを終わらせやすい |
| 勝ち筋をUIで説明しすぎる | 発見の余地を奪う |

## バトル設計指針

### 戦闘の理想展開

標準戦闘は、既存のコアルールどおり次を基準にする。

| ターン | 起きてほしいこと |
|---|---|
| 1から3T | 前中衛が崩れ始める |
| 2から5T | αが中衛/前衛へ引きずり出される |
| 5から7T | α撃破で決着する |

ただし、すべてのデッキが同じ展開になる必要はない。速攻、耐久、妨害、必殺技短縮などで山は変わってよい。重要なのは、変化の理由がログから読めることである。

### 自動戦闘で守るべきこと

| 原則 | 内容 |
|---|---|
| 決定規則を持つ | 同速、同時処理、対象優先、前進を明文化する |
| 重要状態を表示する | 装甲、軽減、毒、回復封じ、α保護、α露出を隠さない |
| 代表戦を見せる | 100戦結果だけでなく、なぜその勝率になったかを確認できる |
| 早送りできる | 検証時は待たせない |
| ただし初見は追える | 新しい効果は発動者、対象、数値、結果を見せる |

## デッキ構築指針

### デッキは「勝ち筋 + 出力方式 + エンジン + 補助/対策」で見る

構築レビューでは、次の順に分解する。

1. どの勝ち筋か。
2. ダメージや妨害をどう出すか。
3. 何のエンジンで増幅しているか。
4. 遂行を助ける補助は何か。
5. 苦手対面への対策は何か。
6. コストや配置の代償は何か。

例:

```text
勝ち筋: エース遂行
出力方式: 後衛主砲の範囲攻撃 + 必殺技
エンジン: α支援 + 装甲/回復
補助: AG強化、前衛保護
対策: 後衛狙いと防御低下に弱い
代償: 主砲が落ちると勝ち筋が細い
```

### シナジーは報酬として残す

個別カード点では弱く見えるカードが、特定デッキで強くなることは好ましい。

ただし、次の状態になった場合は調整対象にする。

| 状態 | 対応 |
|---|---|
| そのシナジーが全デッキの正解になる | 汎用性、対象、持続、コストを見直す |
| 対策しても結果が変わらない | 回答札、対象条件、発動速度を見直す |
| ミラーが膠着する | 決着手段、必殺技、毒/防御低下/貫通を増やす |
| 主軸1枚が落ちた瞬間に終わる | 代替ルートか、主軸依存を許容するデッキタイプとして明記する |

## UI/UX指針

### 画面が担う役割

| 画面/要素 | 役割 |
|---|---|
| カード一覧 | 探す、比較する、採用候補を見つける |
| カード詳細 | 効果、対象、式、位置ごとの役割を確認する |
| 盤面 | 配置制約、α保護、地形、対象範囲を理解する |
| 戦闘リプレイ | 何が起きたかを見る |
| 戦闘ログ | なぜ起きたかを読む |
| 検証結果 | 勝率以外の原因指標を見る |

### UIで避けること

| 避けること | 理由 |
|---|---|
| 大量の説明文を常時表示する | 構築画面の比較速度が落ちる |
| 役割タグで答えを出しすぎる | プレイヤーの発見が弱くなる |
| 状態変化を色だけで示す | 色だけでは意味が伝わらず、アクセシビリティも弱い |
| ログと演出が食い違う | 信頼できない |
| 専門用語を増やしすぎる | ルール理解の負荷が上がる |

## バランス調整指針

### 調整順序

1. まず単体性能の明らかなコスト詐欺を直す。
2. 勝ち筋ごとに標準候補を作る。
3. 総当たりで勝率、決着ターン、引き分け率を見る。
4. 代表戦ログで、実際にどの勝ち筋が遂行されたか確認する。
5. 強すぎる場合は、シナジー全体ではなく原因要素を調整する。
6. 弱すぎる場合は、数値だけでなく対象、位置、AG、必要ターン、支援先を見る。

### 調整対象の見方

| 問題 | 先に見る場所 |
|---|---|
| 決着が早すぎる | AG、初撃火力、サーチ対象、低HP狙い、α露出速度 |
| 決着が遅すぎる | 回復量、装甲持続、決着手段、必殺技必要ターン |
| 特定カードが必須 | コスト効率、対象範囲、汎用性、代替カード不足 |
| 特定勝ち筋が弱い | 生成条件、主軸枚数、支援到達、対策されすぎ |
| 対策不能 | 回答札の発動速度、対象到達、効果量、配置条件 |
| 運が強すぎる | 乱数幅、再現性、ログ上の説明、勝率の分散 |

## 著名思想とこのゲームへの適用

この章は、著名なゲームデザイン思想をそのまま信条にするものではない。各思想を、このゲームの設計判断へ翻訳する。

### 桜井政博氏: リスクとリターン

要約:

ゲーム性の中心を、リスクとリターンの駆け引きとして捉える。プレイヤーは、危険を引き受けることで報酬に近づく。

このゲームでの適用:

| 原則 | 適用 |
|---|---|
| 強い行動には危険を置く | 高火力は前衛限定、低耐久、高コスト、遅い必殺技などで制御する |
| 安全な行動はリターンを抑える | 後衛から広く届く支援や攻撃は、威力、対象、必要ターンを抑える |
| リスクを読めるようにする | 対象マス図、α保護、行動順、状態チップを見せる |
| 駆け引きを盤面に置く | 前進、同列、地形、α露出をリスク/リターンの主装置にする |

注意:

リスクを単に理不尽な罰にしない。プレイヤーが事前に予測でき、敗北後に「次はこうしよう」と思えるリスクにする。

### Sid Meier氏: 面白い選択とプレイヤー心理

要約:

ゲームは、状況依存の面白い選択によって強くなる。また、プレイヤーがどう感じるかは、数理的な正しさと同じくらい重要である。

このゲームでの適用:

| 原則 | 適用 |
|---|---|
| 選択肢にはトレードオフを作る | 火力、防御、速度、対象、地形、コストを同時に最大化させない |
| 常に正解の選択を作らない | 万能カード、万能地形、万能αを避ける |
| 心理的公平性を見る | 同速処理、乱数、対象選択、軽減理由はログで説明する |
| プレイヤーの時間を尊重する | 検証と再構築の往復を速くする |

注意:

「選択肢が多い」だけでは面白くならない。比較可能で、状況によって価値が変わり、結果が読める選択にする。

### MDAフレームワーク: Mechanics / Dynamics / Aesthetics

要約:

ゲームを、ルールや数値である Mechanics、そこから生じるプレイ上の振る舞いである Dynamics、プレイヤーが受け取る体験である Aesthetics に分けて見る。

このゲームでの適用:

| 層 | このゲームでの例 |
|---|---|
| Mechanics | 3x3盤面、前進、α保護、コスト、行動順、地形 |
| Dynamics | 前衛崩壊、α露出、支援役狙い、エース保護、メタ対策 |
| Aesthetics | 読み勝った、構築が機能した、負け筋が分かった、次を試したい |

設計時は、下から積むだけでなく上から逆算する。

```text
与えたい体験
  -> 起きてほしい戦闘展開
  -> 必要なルール、カード、表示
```

### Raph Koster氏: 楽しさは学習から生まれる

要約:

ゲームの楽しさは、パターンを見つけ、理解し、習熟していく過程と深く結びついている。

このゲームでの適用:

| 学習対象 | 設計上の支援 |
|---|---|
| αを守る/倒す | 教材デッキ、明確な勝利条件、α露出表示 |
| 対象条件を読む | 対象マス図、行動説明、ログ |
| 勝ち筋を組む | 勝ち筋別プリセット、検証指標 |
| メタを読む | 対策候補、苦手対面、カード検索 |
| 高度な最適化 | AG、同速処理、必殺技到達、地形シナジー |

注意:

すべてを最初から説明しない。最初は基本勝利条件を理解できればよい。深い構造は、プレイと検証の中で段階的に見つかるようにする。

### Mark Rosewater氏: 制約、プレイヤーの問題発見、カードゲーム運営

要約:

制約は創造性とプレイの面白さを生む。プレイヤーは問題の発見に優れているが、提示する解決策をそのまま採用するとは限らない。

このゲームでの適用:

| 原則 | 適用 |
|---|---|
| 制約を恐れない | コスト、枚数、配置、地形、α指定でデッキ個性を作る |
| プレイヤーの不満を原因に分解する | 「強すぎる」を、速度、対象、対策不能、ログ不明瞭へ分ける |
| すべての層に愛されようとしすぎない | 構築検証型ゲームとして、深い読み合いを核にする |
| カードプールは環境を作る | 単体カードではなく、回答札、代替札、勝ち筋分布で見る |

注意:

制約は、ただ不自由にするためではない。選択を面白くし、デッキに輪郭を与えるために使う。

## 一般セオリー

### Depth と Complexity を分ける

| 概念 | 意味 |
|---|---|
| Depth | 少ないルールから多くの判断が生まれる深さ |
| Complexity | 覚える情報量、例外、処理の多さ |

目標は、高Depth、低から中Complexityである。カード本文、UI用語、例外処理でComplexityを増やす前に、既存ルールとの相互作用でDepthを作れないかを考える。

### Dominant Strategy を避ける

どの相手にも、どの地形にも、どの配置にも強い選択は、ゲームを狭くする。

支配戦略が見つかった時は、弱体化だけでなく、次も検討する。

| 方法 | 内容 |
|---|---|
| 対策札を増やす | 強いデッキに刺さるが他にも用途があるカードを作る |
| 代替札を増やす | 同じ役割に別の弱点を持つカードを作る |
| 条件を絞る | 対象、位置、地形、分類、必要ターンで適用範囲を狭める |
| 報酬を分ける | 火力、防御、速度、安定性を1枚に集めない |

### Rock-Paper-Scissors は硬くしすぎない

相性は必要だが、完全なじゃんけんにすると構築後の学習が浅くなる。

目標は、相性差があっても配置、α指定、補助カードの差し替えで結果が動く状態である。苦手対面の勝率が0%に近い場合は、対策不能になっていないか確認する。

### Readability は強さの一部である

カードが強いか弱いかだけでなく、読めるか、比較できるか、ログで理解できるかも設計品質に含める。

読みづらいカードは、実際の勝率が適正でも体験を悪くする。特に自動戦闘では、結果が見えない強さは不信につながる。

### Onboarding は教材デッキで行う

長いチュートリアルより、意図が明確な教材デッキを使う。

教材デッキは、1つの学習テーマだけを強く出す。

| 教材テーマ | 学ばせること |
|---|---|
| 鼓舞掃射 | AT支援から範囲攻撃へつなぐ |
| 先制集中 | AGで行動順を作る |
| 装甲護衛 | 確定数をずらす |
| 回復粘り | 回復で主軸行動回数を増やす |
| α特性軸 | α指定がデッキ全体へ影響する |
| エースα | 支援を集めて高出力個体を通す |

## 仕様追加チェックリスト

新しいルール、カード効果、UI、検証機能を追加する前に確認する。

```text
1. この追加は、どの体験を強くするか。
2. どの勝ち筋、出力方式、構築エンジンに関わるか。
3. プレイヤーの選択は増えるか。それは面白い選択か。
4. 強い場合、リスク、条件、代償は何か。
5. 対策手段はあるか。実戦で間に合うか。
6. 対象、発動理由、数値変化をUIとログで表示できるか。
7. 既存のカード本文やUIを重くしすぎないか。
8. 勝率以外に、どの指標で成功/失敗を判断するか。
9. 初心者が誤読しやすい点は何か。
10. 世界観上の魅力はあるか。ルール理解を邪魔しないか。
```

このうち 4、5、6 に明確に答えられない仕様は、実装前に設計を戻す。

## アンチパターン

| アンチパターン | なぜ悪いか |
|---|---|
| 強カードの数値だけで環境を作る | 構築の読み合いではなく所持/採用の差になる |
| 全カードに複雑な個性を持たせる | 比較不能になり、デッキ構築が疲れる |
| 対策札を狭くしすぎる | 引けた/持っている時だけ勝つ硬い相性になる |
| 支援カードを低コスト高汎用にする | ほぼ全デッキの固定枠になる |
| 回復と装甲だけで耐久を成立させる | 勝ち筋ではなく時間稼ぎになりやすい |
| 戦闘ログなしに自動処理を増やす | 負けた理由が分からない |
| 世界観語で基本UIを置き換える | ルール理解が遅くなる |
| 仕様追加で既存の判断を無効化する | 過去の学習価値が落ちる |

| タイミング | 更新内容 |

