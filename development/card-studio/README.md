# カード設計室 / Card Studio

新カードを定型フォームで設計し、効果・設計意図・調整履歴を開発用DBへ保存するUI。iPhone向けの公開版と、PCでファイル保存するローカル版がある。

## iPhoneで使う

[カード設計室をSafariで開く](https://mcotto033.github.io/game_development/card-studio/)。PCの起動は不要。「保存」でこの端末のブラウザ内DB（IndexedDB）へ記録する。カード案・画像・設計メモを公開サーバーへ送信しない。

- PCとは自動同期しない。「DB書き出し」でJSONをiPhoneの「ファイル」などに保存し、PC側の「取り込み」で受け渡す。
- ブラウザや端末を変えると別のDBになる。通常のSafariタブを使用し、サイトデータを削除する前にはJSONを書き出す。
- 更新前のデータは端末内にもバックアップする。「前回の保存を書き出す」から直前の版をJSONに取り出せる。履歴とバックアップは自動削除しない。
- 二つのタブで同時に編集した場合、古い版からの上書きを拒否し、入力中の内容を画面に保持する。

GitHub Pagesには画面を構成する6ファイルだけを配置する。開発用DB・バックアップ・テスト・ローカルサーバーはPagesへ配置しない。

## PCのローカル版を起動

Node.js 22以上を使い、プロジェクトのルートで実行する。追加パッケージ・外部サービスは不要。

```powershell
node development/card-studio/server.js
```

[カード設計室を開く](http://127.0.0.1:4317/)。`start.ps1` からも起動できる。終了は起動したターミナルで `Ctrl+C`。

ポートが使用中の場合は `$env:CARD_STUDIO_PORT = '4318'` を設定してから起動し、4318番を開く。同じDBを扱うサーバーは同時に1つだけ起動する。保存の競合検出は同じサーバーにつながる複数タブを対象とする。

## 最短の使い方

1. 「新しいカード」から白紙・攻撃型・支援型を選ぶ。サンプル名・数値は入力例で、採用カードではない。
2. 「基本情報」で名前、レアリティ、コスト、分類、HP/AT/AG、イラスト、得意地形、特性を入力する。
3. 「行動・効果」で前衛・中衛・後衛・必殺技・αスキルを選び、「この枠を使う」を設定する。
4. 対象マスをクリックし、効果種類・量・期間・条件を入力する。2効果なら矢印で実行順を変える。
5. 「設計メモ」に意図・用途・性能評価・検証計画などを記入する。「調整履歴」に今回の変更理由や検証結果を記入する。
6. 「保存」または `Ctrl+S`。入力途中でも下書き保存でき、更新時には変更前後の記録とバックアップが残る。

既存の設計は「複製」して次のカードのたたき台にできる。複製は新しい設計IDを発行し、元の記録を保持する。ゲームカードIDと調整履歴は引き継がず、設計メモに複製元を記す。

左のライブラリでは名前・効果名/内容・設計メモ・過去の調整履歴・タグ・設計IDで検索し、下書き／検証中／採用／保留／見送りで絞り込む。五つの行動枠を区別して種類アイコンを表示する。設計上の「採用」は管理ラベルで、ゲーム本体への登録操作ではない。

## 入力様式と表示規格

本UIは開発段階の表示確認を担う。以下に入力規格をまとめる。ローカル開発時の詳細な正本は `docs/card-presentation-standard-v1.md`、`docs/card-development-notes-v1.md`、本体UIの作業一覧は `docs/card-ui-implementation-checklist-v1.md`（この公開単位には含めない）。

| 項目 | 入力・表示 |
|---|---|
| 基本情報 | 必須16項目の枠。C/R/SR/UR、通常コストは数字、αコストは採用時の総コストとして `α3` 等 |
| イラスト | PNG/JPEG/WebP、1枚2MiBまで。開発DBに埋め込む。出典メモは開発用 |
| 分類 | 分類選択＋アイコン。クリック・タップで分類名と説明 |
| 得意地形 | 複数選択し全アイコンを表示。未選択は空欄。クリックで得意地形の説明と全地形名 |
| 特性 | 共通の一覧から選択。数値と効果量（例：`AT×1.0`）は独立して入力。クリックで共通説明と効果量。0件は「なし」 |
| 五つの行動枠 | 枠ごとに固有名、共通の発動時点・条件、最大2効果。無効は「なし」、入力済みデータは保持 |
| 効果の順序 | 上から順に実行する設計として記録。D4の同AG解決規則を変更するものではない |
| 対象 | 味方・敵の3×3マス。範囲内すべて／サーチを選ぶ。サーチは候補範囲＋選定条件＋数＋同値規則＋代替条件 |
| 自身の位置・相対対象 | `●` は前衛行動なら前衛中央、中衛行動なら中衛中央、後衛行動なら後衛中央。αスキル・必殺技は配置未指定のため中衛中央で仮表示。相対対象はこの位置を基準に描画する |
| 効果量 | 能力値×倍率／固定値／割合／自由記述／量なし。倍率入力は0.05刻み。自由記述は式を計算・実行しない |
| 参照元 | 自身のATは `AT`。他は `対象のAT`、`自身の最大HP` など明記 |
| 条件付き効果量 | 一つの効果に通常量と条件成立時の量を併記。二重の実行にしない |
| 期間 | 即時は表示省略、持続は `2T` 等、常時は `常時`。必殺技の必要ターンは固有欄に `5T` 等 |

未入力項目はプレビュー下部に表示する。これは下書きの記入漏れ確認であり、ルールの整合・採点・ゲーム採用可否を自動判定するものではない。新しい地形名も追加でき、未定義の地形アイコンには仮記号を使う。地形の補正値や正式アイコンは採用時に定義する。

### 新しい効果を追加する

「効果の定義を管理」または効果内の「新しい効果種類」から、次を登録する。

- 定義ID：英小文字から始まる英数・`_`・`-`。作成後は固定。
- 効果名、種類アイコン、共通説明。
- 必要なら専用パラメーターを追加する。項目名・キー・入力型（文字／数値）の組を最大20個。例：結界名、重ね数、移動先など。

登録すると全カードから選べる。カードごとの対象・量・期間と組み合わせるため、効果のたびにコードを書き換える必要はない。定義編集は、その定義を参照する全カードの表示に影響する。IDの意味を別物に変える場合は新IDで作成する。定義変更の過去版はDBバックアップに残る。

**新効果の登録は設計データの登録。戦闘エンジンで実行する処理は別途実装する。** 任意のJavaScript実行やゲームデータへの直接書き込みは提供しない。

### 共通特性と効果量

「共通特性」から選ぶ。初期候補は「装甲」「待ち伏せ」。「共通特性を登録」で名前・共通説明を一度登録すると、別のカードでも選択できる。数値欄を維持し、別の効果量欄で `AT×1.0` などを記述する。待ち伏せなら共通説明は「常時反撃状態」、反撃倍率はカード別の効果量となる。特性を選び直しても数値と効果量を消さない。

以前の自由記入特性もそのまま読み込める。共通特性を選び直すまで元の名称・説明・数値を保持する。追加した共通定義はDB書き出しに含まれ、別端末でも取り込める。

対象図の旧データも読み込める。旧形式の相対対象は中央基準のまま保持し、描画時に行動枠へ投影する。新たに編集した相対味方範囲は `target.allyOffsets`（自身からの行・衛の差）を優先し、`ally` は旧形式互換用とする。盤外の相対指定を表示だけのために削除しない。「自身」ボタンは各行動枠の自身を選ぶ。絶対範囲の対象マスは位置補正しない。

## 保存・履歴・入出力

| 場所／操作 | 内容 |
|---|---|
| 公開版の端末内DB | カード案・メモ・履歴・追加効果定義をこのブラウザに保存。PCとは独立 |
| `data/library.json` | PCローカル版の開発用DB。カード案・メモ・履歴・追加効果定義を保存 |
| `data/backups/library-*.json` | PCローカル版では更新直前のDBを毎回複製。自動削除しない |
| 保存 | DB全体を保存。実際に変更された設計だけ履歴追加。検証結果だけの記録も可 |
| 調整履歴 | 時刻、理由、検証・学び、採否、フィールドごとの変更前後。画像の差分はデータ長を記録し、実画像の旧版はDBバックアップで保持 |
| DB書き出し | 未保存の編集・入力中の履歴メモも含むライブラリJSON。ブラウザのダウンロード先へ出力 |
| 取り込み | Card Studio v1のライブラリJSONをマージ。取り込み後に保存して確定 |
| 仕様JSON | 選択カードの表示・効果仕様と使用する効果定義。設計メモ・履歴・出典メモを除外。戦闘エンジン用の実行データではなく、DB取り込み用ファイルとも別形式 |

取り込み時、IDと内容が同一のカードは重複させない。同IDで異なるカードは**履歴を維持した取込コピー**として新しい設計IDを付ける。元カードは保持する。同じ効果IDの定義内容が異なる場合は取り込み全体を中止し、ID整理を求める。

保存中の再編集を止めて、保存成功後に画面を更新する。他タブで保存済みなら409で拒否し、編集中の値は画面に保持する。「DB書き出し」で退避→再読み込み→退避ファイルを取り込むと競合する案を別々に確認できる。

保存ボタンを押すまで編集内容はメモリ上にある。ページを離れる前に保存する。未保存時はブラウザの離脱確認を利用するが、iPhoneのアプリ終了などでは表示されないことがある。公開版の正本はIndexedDB、PCローカル版の正本はJSONファイルで、localStorageは使用しない。ライブラリ上限はカード・追加効果定義それぞれ1000件、1回の保存25MiB。画像を多く埋め込む場合は小さい画像を使用する。端末容量不足時は保存を中止し、編集中のデータを保持する。

### PCローカル版の保存ファイルが壊れた場合

1. サーバーを終了する。
2. 現在の `data/library.json` を別名で退避する。
3. `data/backups/` から復元したいJSONを確認し、そのコピーを `data/library.json` に置く。
4. サーバーを再起動する。

破損時に空DBとして上書きすることはない。復元作業前に退避し、残したい新しい編集があれば別途書き出す。`data/` はこのディレクトリーの `.gitignore` でGit対象外にしている。

## データ構造

```text
library { schemaVersion: 1, revision, cards[], definitions[], traitDefinitions?[] }
  cards[]
    id, gameCardId, artCredit, status, tags, createdAt, updatedAt
    card { name, artwork, cost, alphaCost, rarity, classification,
           terrains[], traits[], hp, at, ag, skills { front, middle, rear, ultimate, alpha } }
      skill { enabled, name, trigger, condition, turns, effects[] }
        effect { id, typeId, target, amount, duration, condition, alternate, details, params }
    notes { intent, strength, usage, winPlan, synergy, counter, references,
            scoring, risks, testPlan, results, learning }
    history[] { id, at, reason, result, decision, changes[] { path, before, after } }
  definitions[] { id, name, icon, description, parameters[] { key, label, type } }
  traitDefinitions[] { id, name, description }
  card.traits[] { definitionId?, name, value, effectAmount?, description }
```

カード仕様は `card`、開発情報は同階層の `notes` / `history` などに分離する。フォルダー自体もゲームの実行資産から独立する。既存カードの自動移行と戦闘エンジン用アダプターは未実装。版・記録者・実装参照は、現版では設計メモ／検証条件に記録する。

## 実装判断と次の接続点

- 2026-09-18、ユーザーの新規UI作成依頼に基づく。外部DBサービスや表計算を使う案と比較し、追加設定が不要で、可変の効果パラメーターと履歴を保ちやすいローカルJSON＋Node.jsを採用した。
- 単一設計者・ローカル利用を前提とする。複数端末で同時編集する、画像量が増える、横断集計が必要になる段階でSQLiteや共有DBへの移行を検討する。
- 表示規格の細部を将来のゲームUIへ移すときは `renderPreview`、効果入力は `effectForm`、値の検証・書式は `model.js` を参照する。既存C2の完了条件とは区別する。
- SYS/BAL/IDEAに対する位置：新カード設計を支える**開発ツールの実装**。SYS変更やBAL候補の採否には介入しない。次の接続点はカード案の作成・試用、その後の必要に応じた本体データ変換。
- 着手時は別タスクがBAL-02dを編集中だったため、本フォルダーに編集を限定した。別タスクがidleになったことを確認後、開発DB要件と引き継ぎ入口にリンクを追加した。既存ゲーム・共通検証スクリプトは変更していない。
