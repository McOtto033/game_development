# カード設計UI 改良版

入力ツリーDBから、選択肢・表示条件・状態ごとの専用入力欄を生成する設計用UI。旧版 `development/card-studio/` と並行して使用する。

公開URL: https://mcotto033.github.io/game_development/card-studio-v2/

## 起動

Node.js 22以上で `node development/card-studio-v2/server.js` を実行し、`http://127.0.0.1:4318/card-studio-v2/` を開く。PowerShellではこのフォルダーの `start.ps1` も使用できる。

## 編集と保存

- 「基本情報」「行動」「特性」「メモ」に分け、詳細条件は折り畳む。攻撃・回復の量、装甲の被ダメージ倍率、守護の肩代わり割合などは別々のフォームになる。
- 行動の最大効果数は通常・αが2、必殺が3。攻撃回数・効果セット数・行動セット数はそれぞれ別項目。
- カード、画像、設計メモ、保存履歴、使用した定義DBをブラウザのIndexedDBに保存する。サーバーへ送信しない。通常のファイルへの自動保存・端末間同期は行わない。
- 「保存」で端末内に記録。「DB書き出し」で移送・バックアップ用の全データを取得。「設計JSON」には有効な枝だけを出力する。入力途中の数値・空欄は下書きとして保存できる。
- 別タブで保存された場合は上書きを拒否する。編集内容は保持されるので、DBを書き出してから再読込・取込する。
- 旧版とURL・IndexedDB名・JSON形式を分離。旧版DBを取り込むと、自由文・画像・メモ・履歴を含めた原本を保管する。カードへの自動変換はしない。「旧版データ」から原本JSONを書き出せる。

## 定義DBの更新

`schema.json` は `outputs/card-ui-tree-20260928/カード基礎情報DB_入力ツリー_v2.schema.json` の複製。元のExcel・JSONは変更していない。Excelの直接取込には未対応。Excelの変更内容や自然言語の相談をチャットで固定キー・型・選択肢・条件へ整理し、対応する定義JSONを作成する運用を想定する。

「定義DB」→「定義JSONを取り込む」→「この定義を適用」で、手元のカードの値を保ったままフォームを更新する。旧定義は履歴に残る。不正な既定値、必須構造の削除、現用値と互換性のない型変更は適用前に拒否する。基本キーと5つの行動枠はUIとの契約なので維持する。新特性・状態は `definitions` と専用 `forms` で増やせる。

候補仕様・未接続のルールもDBに含む。入力フォームを追加しても戦闘エンジンが自動実装されるわけではない。設計JSONは `runtimeReady:false`。実戦への反映には各ルールの確定、エンジン接続、変換と検証が必要。

## 検証

`node --test development/card-studio-v2/model.test.js`

PlaywrightとMicrosoft Edgeが使える環境では `node development/card-studio-v2/browser.test.js`。必要なら `PLAYWRIGHT_MODULE` でモジュールのパスを指定する。`CARD_STUDIO_V2_URL` を指定すると公開版を同じ項目で確認する。ブラウザ検証は専用の一時プロファイルを使う。

公開対象はHTML・CSS・JavaScript・共通定義JSON・アイコンだけ。利用者のDB、画像、メモ、検証の生成物は公開しない。
