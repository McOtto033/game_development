# カード設計スキーマ v0

## 目的

カードを設計する時に、UIへ出す情報と内部だけで管理する情報を分ける。

UIは「このカードで何が起きるか」を明確にする。内部メモは「なぜ強いか」「どの勝ち筋を想定しているか」「どう対策されるべきか」を管理する。勝ち筋や対策をUIで説明しすぎると、デッキ構築の発見が弱くなるため、原則として内部限定にする。

## 基本方針

分類、特性、役割、地形、行動、必殺技などの中央定義候補は [中央定義候補 v0](central-definition-candidates-v0.md) に分けて管理する。分類、特性、得意地形、地形、属性の切り分けは [カードレイヤー設計メモ v0](card-layer-design-memo-v0.md) と [カード分類・特性・属性メモ v0](card-taxonomy-traits-attributes-v0.md) を参照する。実装に近い最優先データ形は [コア中央定義フォーマット v0](core-data-definitions-v0.md) を正本にする。

| 方針 | 内容 |
|---|---|
| 明示する | ステータス、コスト、行動、必殺技、分類、特性、α特性、地形適性 |
| 粒度を落として任意表示 | 役割タグ。攻撃/防御/支援/妨害/回復程度に留める |
| 明示しない | 勝ち筋、対策、想定コンボ、危険な組み合わせ、採点内訳 |
| 匂わせる | 分類、特性、地形適性、行動配置、図鑑テキスト |

UIで見せるべき情報は、プレイヤーがルールとして納得できるものに限る。カード設計者が意図した使い方は、分類、特性、効果から推測できる程度に留める。

## UI表示項目

| 項目 | 表示 | 備考 |
|---|---|---|
| カード名 | 必須 | 種名、俗称、観測名に寄せる |
| レアリティ | 必須 | 性能差だけでなく複雑さ、希少性、世界観上の存在感にも使う |
| HP/AT/AG | 必須 | 数値理解のため略称を維持 |
| コスト | 必須 | 通常採用時のコスト |
| αコスト | 必須 | α指定時のコスト。短縮表示は `α6` など |
| 分類 | 必須 | 生物としての大分類。世界観とコンセプトデッキの土台 |
| 地形適性 | 原則表示 | 地形とシナジーするカードを探しやすくする |
| 属性 | 条件付き | 攻撃や状態の性質。属性参照、耐性、弱点を実装した段階で表示する |
| 前衛行動 | 必須 | 実際の行動名と効果説明 |
| 中衛行動 | 必須 | 同上 |
| 後衛行動 | 必須 | 同上 |
| 必殺技 | 必須 | 指定ターン数経過後、どのマスでも使える大技 |
| 必殺技必要ターン | 必須 | 初回/再発動までのターン数 |
| 特性 | 必須 | 生態に由来する常時/条件/誘発効果。飛行、水棲、捕食、擬態など |
| α特性 | 必須 | α指定時だけ機能する能力 |
| 役割 | 任意表示 | 参考情報。検索/採点の主軸にはしない |
| 図鑑テキスト | 任意表示 | 戦略の匂わせと世界観補強に使う |

## 内部限定項目

| 項目 | 含める内容 |
|---|---|
| カードコンセプト | 設計役割、想定勝ち筋、想定シナジー、想定対策、苦手な相手 |
| 性能評価点数 | ステータス点、行動点、必殺技点、特性点、α特性点、危険フラグ、推奨コスト/レアリティ |
| 調整履歴 | 変更理由、変更前後の数値、テスト条件、結果、次回確認点 |

内部限定項目は、カード詳細画面や図鑑には出さない。以前分けていた `設計役割`、`想定勝ち筋`、`想定シナジー`、`想定対策`、`苦手な相手` は、トップレベルでは `カードコンセプト` に統合する。`危険フラグ` は `性能評価点数` のチェック項目、`テスト条件` は `調整履歴` の一部として扱う。

## 性能評価点数とバランス

性能評価点数に対して、コストとレアリティでバランスを取る。

ただし、役割を分ける。

| 要素 | 主な役割 |
|---|---|
| コスト | 1デッキ内での採用負荷、同時採用できる強カード数を制御する |
| αコスト | α指定時のデッキ構築負荷と、α特性の強さを制御する |
| レアリティ | 複雑さ、希少性、演出価値、枚数制限、環境出現率を制御する |
| 枚数制限 | デッキの再現性、同名カード連打、必殺技短縮などの極端な構築を制御する |

基本的には `性能評価点数 -> 推奨コスト帯` を出し、実測で調整する。レアリティは同コスト内の上限を少し押し上げてもよいが、単純な上位互換を大量に作るためには使わない。

高レアカードの望ましい強さは、単純な数値優位ではなく、以下に寄せる。

| 方向 | 内容 |
|---|---|
| 高い上振れ | 条件達成時に強いが、対策や不発もある |
| 高い複雑さ | コンボ、地形、分類、特性、必殺技などを扱う |
| 高い演出価値 | 必殺技やα特性が派手 |
| 構築制限込みの強さ | 枚数制限や高コストで再現性を抑える |

レアリティや枚数制限があっても、対策不能なカードは許容しない。対策不能な強さはコストを上げてもゲーム体験を悪化させる。

## 必殺技

必殺技は、指定ターン数経過後に使用可能になる位置非依存の大技とする。膠着状態を崩す変化点であり、必殺技短縮効果は勝ち筋を早める構築エンジンとして扱う。

基本ルール案:

| 項目 | 方針 |
|---|---|
| 発動条件 | 必殺技必要ターンを満たした生存カードが発動可能 |
| 発動位置 | 前衛/中衛/後衛のどこにいても同じ必殺技を使う |
| 発動タイミング | 行動順が来た時、通常行動の代わりに発動 |
| 再発動 | 使用後にカウントをリセットし、必要ターン経過で再使用可能 |
| AGとの関係 | 必殺技が使用可能でも、同一ターン内の発動順はAGに従う |
| 短縮効果 | 残りターンを減らす。0以下になった場合は次の行動機会で発動可能 |

通常行動への上乗せではなく「通常行動の代わり」にする。追加行動にすると、必殺技短縮デッキが火力と通常行動を同時に得て、対策困難になりやすい。

必殺技は破格の性能でよい。ただし、以下のどれかで制御する。

| 制御軸 | 例 |
|---|---|
| 必要ターン | 4T、5T、6Tなど |
| 対象条件 | α露出時、負傷対象、特定地形上など |
| 自身のリスク | 発動後にAG低下、HP消費、次ターン待機など |
| 短縮制限 | 同一カードの短縮は1ターン1回まで、短縮対象は味方1体など |
| 対策余地 | 妨害、撃破、バリア、配置変更で受けられる |

必殺技短縮デッキは正式なデッキタイプとして許容する。ただし、毎試合ほぼ同じターンに複数必殺技が連鎖して相手の選択余地を消す場合は、短縮量、対象数、AG、必要ターンを調整する。

## カード選択用の内部検索メタデータ

デッキ構築で重要なのは、カードが「どの位置で」「どの種類の効果を」「どの対象へ」使えるかである。役割タグよりも、下記のメタデータを優先して持つ。

実装データでは、カード本体は `frontAction/middleAction/rearAction` に行動IDを持つ。効果要素と対象パターンは中央定義 `ACTION_METADATA` に置き、検索時に展開する。

設計シートやレビュー画面では、確認しやすいように以下の形で併記する。

```text
前衛行動:
  行動ID:
  効果:
    - 効果要素:
      対象パターン:

中衛行動:
  行動ID:
  効果:
    - 効果要素:
      対象パターン:

後衛行動:
  行動ID:
  効果:
    - 効果要素:
      対象パターン:
```

例:

```text
中衛行動:
  行動ID: nervePulse
  効果:
    - 効果要素: AG操作
      対象パターン: 同列の味方
```

```text
後衛行動:
  行動ID: corrosiveSpray
  効果:
    - 効果要素: 範囲攻撃 / 防御低下
      対象パターン: 敵前衛全体
```

```text
中衛行動:
  行動ID: guardedMend
  効果:
    - 効果要素: 回復
      対象パターン: 低HPの味方
    - 効果要素: 装甲
      対象パターン: 低HPの味方
```

この形なら、カード選択画面で以下のような検索ができる。

```text
後衛で回復できるカード
中衛でAG操作できるカード
敵後衛を狙えるカード
範囲攻撃を持つカード
αを守れるカード
必殺技を短縮できるカード
```

## 役割タグ

役割タグはユーザーへの分かりやすさのための参考情報とする。デッキ構築検索や採点では、役割タグではなく `位置 × 効果要素 × 対象パターン` を使う。

### UI役割タグ

| タグ | 表示条件 | 注意 |
|---|---|---|
| 攻撃 | ダメージ行動を主に持つ | 単体/範囲/α狙いまでは行動説明で示す |
| 防御 | ダメージカット、バリア、被ダメージ軽減を持つ | 「要塞役」などは内部限定 |
| 回復 | HP回復を主に持つ | 回復耐久の中核かどうかは内部限定 |
| 支援 | AT/AG強化、地形補助、コスト補助を持つ | コンボ起点と明示しない |
| 妨害 | 弱体、行動阻害、対象逸らし、回復封じなどを持つ | 対策札と明示しない |

1枚のカードに表示する役割タグは最大2つまでを目安にする。3つ以上出るカードは、実際には何をさせたいカードかが曖昧になっている可能性がある。

### 内部役割タグ（後回し）

下記はカードプール監査や自動レポートが必要になった段階の候補。初期カードデータには手入力しない。必要になったら、行動検索メタデータ、特性、必殺技から推定する。

| タグ | 意味 |
|---|---|
| `frontBreaker` | 前衛突破役 |
| `backlineHunter` | 中衛/後衛を狙う役 |
| `alphaProtector` | αを守る役 |
| `alphaPunisher` | α露出を咎める役 |
| `sustainCore` | 回復/防御で長期戦を作る中核 |
| `tempoAccelerator` | AG操作や開幕効果で先手を作る役 |
| `areaPressure` | 範囲攻撃で総ダメージを稼ぐ役 |
| `singleTargetFinisher` | 単体高火力で確定撃破を狙う役 |
| `comboStarter` | 後続効果の条件を作る役 |
| `comboPayoff` | 条件達成時に強くなる役 |
| `terrainEnabler` | 地形コストや地形効果を利用させる役 |
| `classificationLord` | 特定分類を強化する役 |
| `traitLord` | 特定特性を強化する役 |
| `ultimateAccelerator` | 必殺技の必要ターンを短縮する役 |
| `ultimatePayoff` | 必殺技そのものが主な勝ち筋になる役 |
| `ultimateStallBreaker` | 膠着状態を崩す必殺技を持つ役 |
| `antiHeal` | 回復型への回答 |
| `antiBarrier` | バリア型への回答 |
| `stallBreaker` | 膠着を崩す役 |

内部役割タグはUIに出さない。テスト、採点、カードプール設計の管理用とする。ただし、当面の検索/採点の主軸は `位置 × 効果要素 × 対象パターン` とする。

## 分類と特性

分類と特性はどちらもUIに出す。ただし役割は分ける。

| 種別 | 意味 | 例 | UI表示 |
|---|---|---|---|
| 分類 | そのカードが何の生物群か | 魚類、両生類、爬虫類、鳥類、哺乳類、甲殻類、昆虫類、植物、菌類、竜類、無機生命、幻獣、軟体類 | 必須、原則1つ |
| 特性 | 生態に由来する実効果 | 飛行、水棲、捕食、擬態、毒耐性、古代、巨大 | 必須、1〜3個程度 |
| 地形適性 | どの地形で強いか | 海、森、岩山、砂漠、火山、極地 | 別項目で表示してよい |
| 属性 | 攻撃や状態の性質 | 電気、酸、毒、熱、胞子 | 条件付き。原則は行動側に置く |

分類は世界観と分類強化デッキの軸、特性は実際のルール効果と横断シナジーの軸にする。

重要なのは、分類と特性を無理に一致させないこと。鳥類でも飛べる種と飛べない種がいる。魚類と爬虫類のどちらにも水棲種はいる。このズレを使うことで、分類デッキと特性デッキの両方を成立させる。

例:

```text
分類: 鳥類
特性: 飛行
```

```text
分類: 鳥類
特性: 疾走
```

```text
分類: 魚類
特性: 水棲 / 捕食
```

```text
分類: 爬虫類
特性: 水棲 / 古代
```

上記の場合、魚類と爬虫類は分類強化では別デッキになる。一方で、どちらも `水棲` を持つため、海地形や水棲支援では同じデッキに入れられる。

属性は、分類や特性と同じ階層にしない。例えば電気ウナギ型カードは、分類が `魚類`、特性が `水棲 / 発電`、行動属性が `電気` になる。属性名だけで隠し相性を発生させず、AG弱体、麻痺、毒、防御低下などの実効果は効果要素や状態効果へ分解する。

### 特性の定義

特性は、自身の通常行動そのものではない、生態に由来する常時効果、条件効果、誘発効果とする。

| 特性 | ルール効果例 | 設計上の使い方 |
|---|---|---|
| 飛行 | 地形効果を受けない | 地形依存デッキへの対抗、安定配置 |
| 水棲 | 海以外ではAT/AGが0.8倍 | 海デッキ誘導、コストの割に高ステータスなカード設計 |
| 捕食 | 低HPの敵を攻撃する時、ダメージ増加または撃破時強化 | サーチ攻撃、削りとのコンボ |
| 擬態 | サーチ攻撃の対象になりにくい、初回被ダメージ軽減など | 後衛支援役の保護、読み合い |
| 毒耐性 | 毒/継続ダメージを軽減または無効 | 毒環境への回答 |
| 古代 | 必殺技必要ターンが長い代わりに大技が強い、特定地形で強化。妨害耐性も議論候補 | 高コスト/高レア/α向き |
| 巨大 | 最大HPが高いがAG低下、範囲攻撃に強い/弱いなど | α候補、前衛制圧 |

ユーザーメモ上の `水棲` はAT/AG補正のみ。現プロトタイプ文言にはHP補正も含む箇所があるため、本実装時はAT/AGのみへ寄せるかを先に決める。

### 行動に含めるべき効果

自身の特定行動だけに付随する効果は、特性ではなく行動側に含める。

| 特性にしない例 | 行動側での表現 |
|---|---|
| 後衛から攻撃時にダメージ+3 | 後衛行動そのものを高威力にする |
| 中衛からのみ敵後衛を狙う | 中衛行動の対象を敵後衛優先にする |
| 前衛時だけ2体攻撃 | 前衛行動を2体攻撃にする |

特性に置くのは、配置や個別行動を超えてカードの生態として働く効果に限る。

### 初期主要分類

| 分類 | 主な機能 | 特性の付き方 |
|---|---|---|
| 鳥類 | 高AG、奇襲、後衛到達 | 飛行、疾走、擬態など |
| 魚類 | 海地形、高ステータス、捕食 | 水棲、捕食、群体など |
| 爬虫類 | 強攻撃、高HP、古代、大型、捕食。恐竜系と翼竜系も含む | 水棲、古代、巨大、飛行、捕食など |
| 甲殻類 | ダメージカット、前衛維持、反撃 | 甲殻、水棲、毒耐性など |
| 菌類 | 回復、拡散、戦闘不能トリガー | 菌糸、寄生、毒性、群体など |
| 昆虫類 | 低コスト、群体、毒性、擬態 | 群体、飛行、毒性、擬態など |
| 哺乳類 | 標準的なステータス、前衛攻撃、地形適応 | 疾走、群れ、捕食など |
| 竜類 | 高コスト、高AT、属性攻撃、α向き | 飛行、古代、巨大、甲殻など |
| 植物 | AT低め、支援、妨害 | 果実、毒性、擬態など |
| 両生類 | 回復、復活、毒、バフ | 水棲、毒性、再生、擬態など |
| 無機生命 | 高HPまたは防御特性で硬さを出す。低AG寄りも候補 | 結晶、発電、毒耐性、装甲など |
| 幻獣 | 高ステータス、尖った性能 | 古代、巨大、発電、擬態など |
| 軟体類 | アンモナイト、イカ、タコ、貝類など | 水棲、擬態、甲殻、毒性など |

`恐竜` と `翼竜` は独立分類にしない。恐竜系は `爬虫類` + 高ステータス/`古代`/`巨大`、翼竜系は `爬虫類` + `飛行` で特徴づける。

`昆虫類` と `甲殻類` は独立分類を正とする。甲殻類は硬さ/反撃、昆虫類は群体/毒/飛行/擬態で差を出す。`結晶生命` は `無機生命` へ統合し、`結晶` を特性またはカード群テーマにする候補。

分類は生物としてのまとまりなので、分類そのものに共通効果を持たせない。分類を参照する効果は、分類強化、分類対策、分類条件のα特性などで表現する。

### 初期主要特性

| 特性 | 主な機能 | 典型的な弱点 |
|---|---|---|
| 飛行 | 地形効果無視、地形ペナルティ回避 | 対飛行妨害、低HPになりやすい |
| 水棲 | 海で高性能、海以外で弱体 | 地形依存、海を使えない構築で弱い |
| 捕食 | 低HP狙い、撃破時強化 | 防御/回復で確定数をずらされる |
| 擬態 | サーチ回避、初回軽減、対象逸らし | 範囲攻撃、ランダム対象 |
| 毒性 | 継続ダメージ、回復阻害 | 毒耐性、短期決戦 |
| 毒耐性 | 毒/継続ダメージへの回答 | 毒以外には価値が落ちる |
| 群体 | 複数対象支援、肩代わり、数を使った効果 | 範囲攻撃、撃破時効果を相手に与えやすい |
| 古代 | 高コスト、大型効果、強い必殺技。妨害耐性も候補 | コスト制約、初動の遅さ |
| 巨大 | 高HP、前衛制圧、α向き | 低AG、サーチ/割合/貫通系 |
| 発電 | AG操作、麻痺、連鎖攻撃 | 発動前撃破、ダメージカット |
| 甲殻 | ダメージカット、前衛維持、反撃 | 貫通、固定値軽減無視 |

### 分類/特性の付け方

| ルール | 内容 |
|---|---|
| 分類は原則1個 | そのカードが何の生物かを明確にする |
| 特性は1〜3個 | 生態効果、地形依存、体構造、時代性を表す |
| 分類と特性は一致しなくてよい | 鳥類でも飛行なし、爬虫類でも水棲ありにできる |
| 表示タグは合計4個程度まで | 5個以上は焦点がぼやける |
| 参照カードを用意する | 分類強化、特性強化、対策、α特性のどこかで参照する |
| タグだけで強くしない | 統一デッキが自動正解にならないようにする |

## 地形適性

地形適性は分類/特性とは分ける。分類/特性はカード間シナジー、地形適性は盤面構築シナジーを担う。

| UI項目 | 意味 |
|---|---|
| 得意地形 | その地形で能力や行動が強くなる |
| 苦手地形 | 明示する場合は少数に留める |
| 地形参照 | 特性やα特性が特定地形を参照する |

例:

```text
分類: 魚類
特性: 水棲 / 捕食
得意地形: 海
```

```text
分類: 鳥類
特性: 飛行 / 発電
得意地形: 岩山
```

## 危険フラグ

カード作成時に、内部メモとして以下を必ず確認する。

| フラグ | 内容 |
|---|---|
| `stallRisk` | 回復/防御が強すぎて膠着を生む |
| `firstStrikeLock` | AG操作や開幕火力で相手に行動させない |
| `unanswerableAlpha` | α保護やα特性が対策困難 |
| `searchSnowball` | サーチ攻撃が一点突破を容易にしすぎる |
| `aoeOverkill` | 範囲攻撃の総ダメージが見かけより高すぎる |
| `ultimateLoop` | 必殺技短縮で大技が過剰に連発される |
| `ultimateNoCounterplay` | 必殺技発動までの対策余地が少なすぎる |
| `mirrorInstability` | ミラーで同速処理の結果が大きくブレる |
| `tagAutoBuild` | 分類/特性統一が自動正解になりすぎる |
| `hiddenComplexity` | UIに書かれた内容から実際の強さを予測しにくい |

危険フラグが2つ以上立つカードは、コストを上げるだけでなく、条件を狭める、対象範囲を制限する、対策カードを増やすなどの調整を検討する。

## UIで避ける説明

以下のような説明は、カード詳細には出さない。

| 避ける表現 | 理由 |
|---|---|
| このカードは耐久デッキの中核 | 勝ち筋を直接説明しすぎる |
| 後衛を倒す対策札 | 対策構造を明示しすぎる |
| 竜類統一のフィニッシャー | コンセプトデッキの答えを出しすぎる |
| α露出後に勝つカード | 終盤の勝ち筋を説明しすぎる |
| 必殺技短縮デッキの主砲 | 構築の答えを直接示しすぎる |
| 回復耐久メタ | メタ役割が直接的すぎる |

代わりに、行動や特性で自然に伝える。

```text
良い:
分類: 竜類
特性: 古代 / 捕食
後衛行動: 敵中後衛の低HPを狙う
必殺技: 敵全体に大ダメージ
必殺技必要ターン: 5T

避ける:
このカードは後衛支援役を狩るためのカード
```
