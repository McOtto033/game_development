# 効果対象の記述規格 v1

2026-09-18のユーザー指定に基づくカード設計室の入力・保存規格。対象範囲（既存の敵味方3×3、絶対/相対位置）は別欄として維持する。

## 役割を分ける

| 要素 | 決めること | 例 |
|---|---|---|
| 既存の範囲・候補の参照元 | どこから候補を得るか | 敵前衛のマス、自身を攻撃してきた相手 |
| 候補の区分 | 陣営、自身、生存状態 | 敵、味方、敵味方／自身を含む・除く・自身のみ／生存・戦闘不能・不問 |
| 対象条件 | 候補が条件を満たすか。人数は決めない | AT20以上、毒状態、植物分類 |
| 対象の選び方 | 条件に合った候補から何体を選ぶか | 全員、残HPが低い順に1体、AGが高い順に2体 |
| 再判定のタイミング | 条件と選択をいつ実行するか | 効果開始時に一度、各攻撃直前、指定イベントごと |
| 境界の扱い | 同値、対象不在、固定対象の無効化 | 同値を位置順で絞る、対象がいなければその回は不発 |

上から順に適用する。既存の「この効果だけの条件」は効果自体を実行する条件であり、候補カードに対する「対象条件」とは分ける。再判定は対象を選び直す指定であり、発動そのもののタイミングは行動名の下の共通欄で指定する。

候補の参照元が攻撃者等であっても、候補区分・対象条件・選択・再判定を組み合わせられる。マスを使う場合は指定マスと陣営条件の積集合。空マスはカード候補にならない。「全員」でも対象範囲を無視しない。

## 対象条件

### 定型の条件

- ステータス：残HP、HP割合（%）、最大HP、AT、AG、装甲、コスト、αコスト、独自の能力名。
- 比較：以上／以下／より大きい／より小さい／等しい／異なる／最高／最低。割合は0〜100を基準とする値として記述する。
- 状態・特性・現在の地形・得意地形・分類：該当する／しない。既存の候補と自由な名称の両方を使える。現在の地形と、そのカードが得意な地形を混同しない。
- 行動順：直前に行動した／直後に行動する。何番目かを指定でき、1が直前・直後。全体、味方内、敵内のいずれの順番を見るかを指定する。
- 自然言語：まだ定型化していない条件を原文で保存する。式やコードとして実行しない。

### 複合条件

グループごとに以下を指定し、入れ子で組み合わせる。条件内の記載順で意味を変えない。

- **AND**：すべてを満たす。
- **OR**：いずれかを満たす。同じカードが複数条件を満たしても重複した対象にしない。
- **NOT OR**：どの条件も満たさない。`NOT (A OR B)` の意味。

例：`毒 AND (AT ≥ 20 OR 分類＝植物) AND NOT (特性＝待ち伏せ)`。

入力上限はルートを含め合計40項目、入れ子5段。空グループは下書き上「条件なし」とし、子の空グループは記入待ちに表示する。条件全体が空なら区分に合う候補をそのまま次へ渡す。

### 最高・最低と上位X体の違い

「残HPが最低」という条件は、**範囲・参照元・候補区分を適用した時点の候補集合**と比較する。ほかの対象条件で絞る前の集合であり、同率最低は全員が条件を満たす。複数の極値条件でも、各条件が同じ集合を参照するため記載順に依存しない。

「毒状態の中で残HPが低い順に1体」は、対象条件を「毒」、選び方を「残HPの低い順・1体」とする。先に毒で絞り込んでから順位を決める。

このため「残HP最低 AND 毒」と「毒の中の低HP1体」は異なる指定。前者は候補全体の最低HPカードが毒でなければ対象なしになり得る。最低値の比較集合を別にしたい複雑な関係は自然言語の条件へ明記し、後で定型化する。

### 行動順の基準

基準は「自身の今回の行動」。直前は既に行動した順番、直後は判定時点で予定されている行動順を参照する。全体の直前が味方である場合だけ選ぶ指定と、敵を挟んでも味方の中で直前を探す指定を区別する。

同AGの並びはゲーム側の確定した決定論的順序に従う。この規格だけで戦闘エンジンの同AG処理を変えない。自身の行動を基準にできない発動では自然言語の条件に別の基準点を記述する。

## 対象の選び方

1. **全員**：対象条件に合うカードすべて。対象数Xや順位は使わない。
2. **ステータス順にX体**：条件を通過した候補を高い／低い順に並べ、異なるカードを最大X体選ぶ。候補がX体未満なら存在する候補全員。
3. **その他**：対象数も含めて自然言語で記述する。可変人数、複数の優先順位、過去の選択対象の除外など、まだ定型化していない選び方を残せる。

同値は「位置順でX体へ絞る」「境界の同値を全員含む」「優先順を自由記入」の三つ。境界の同値を全員含む指定ではX体を超え得ることをプレビューに明示する。

新書式の位置順は前衛→中衛→後衛、同じ衛では左→中央→右。同じ位置が両陣営にある場合は味方→敵。これは設計記述上の既定値であり、本体の対象選択ルールの変更ではない。既存の自由文の同値規則はそのまま保持する。

## 再判定

| 選択 | 意味 |
|---|---|
| 効果開始時に1回 | 対象条件・並び順を一度だけ評価し、選んだカードをその効果の残り回数で保持。マスの占有者を毎回取り直す意味ではない |
| 各回の実行直前 | 毎回、最新の範囲/参照元・区分・条件・並び順で選び直す。再選択で前回と同じカードになることもある |
| 指定イベントごと | 攻撃を受ける/攻撃する/ダメージ/回復/状態付与/行動/独自イベントごとに評価。発動条件も共通欄に記録する |

例：敵Aの残HPが10、敵Bが12、1回のダメージがAを倒す量で、3回攻撃する場合。

- **固定**：開始時にAを選ぶ。Aが倒れてもBへ乗り換えない。残りは「対象なし／無効時」の規則に従う。
- **各回**：1回目はA、Aが倒れた後の2回目は生存中のBを選ぶ。Bも倒れ、ほかの候補がいなければ対象不在の規則に従う。

対象不在・無効時は「その回は不発（補充なし）」「この効果の残り回数を打ち切る」「自然言語で指定」のいずれか。固定時の『無効』は戦闘不能・退場などの解決不能を指し、条件不成立になっただけでは再判定しない。各回での選び直しは不在時の処理より先に行う。

このアプリは設計・表示・保存を行う。実際の攻撃解決、同AG途中の観測時点、予定行動が変わった場合の再計算、イベントの発火処理はゲーム本体へ接続するときの実装・検証対象。

## 例の設定

| 表現 | 条件 | 選択 | 再判定 |
|---|---|---|---|
| AT20以上の敵のうちAGが高い2体 | AT ≥ 20 | AG降順・2体 | 効果開始時に1回 |
| 毒または植物分類の味方全員 | 毒 OR 分類＝植物 | 全員 | 効果開始時に1回 |
| 味方内で直前に行動したカード | 行動順：直前・1番目・味方内 | 全員 | 効果開始時に1回 |
| 全体で次に行動する敵 | 行動順：直後・1番目・全体、区分：敵 | 全員 | 効果開始時に1回 |
| 最低HPの敵を固定して3回 | 条件なし、区分：敵・生存 | 残HP昇順・1体 | 効果開始時に1回 |
| 攻撃ごとに最低HPの敵を探して3回 | 条件なし、区分：敵・生存 | 残HP昇順・1体 | 各回の実行直前 |

最後の二つは効果量 `AT×0.25`、攻撃回数 `3` などを同じ効果に記録する。倍率と回数を対象指定へ重ねて保存しない。

## データと移行

新書式は `effect.target.query` に保存する。範囲は従来どおり `basis` / `ally` / `enemy` / `allyOffsets`、参照元は `source` / `context`。`query` があるときは旧 `selection` / `count` / `rule` / `tie` / `fallback` を選択の正本として使わない。

```text
query { version:1, side, self, life, conditions, pick, timing, absence }
conditions { kind:'group', op:'all'|'any'|'none', items:[条件またはグループ] }
pick { mode:'all'|'rank'|'custom', stat, customStat, direction, count, text, ties, tieText }
timing { mode:'once'|'each'|'event', event, text }
absence { mode:'skip'|'stop'|'custom', text }
```

旧データは読み込みだけで書き換えない。「条件を分けて編集する」を押したときだけ新書式を作る。標準テンプレートの残HPサーチ・全員指定は対応する定型欄へ移す。独自の自由文は解釈・分解せず人数も含めて自然言語の選択欄へ写す。範囲、旧文、同値規則、対象不在時の指定を保持する。

自然言語の条件はグループ内の独立項目として保存するため、後からその項目だけ定型条件へ置き換えられる。新しい例を分類する際は、候補/条件/選択/判定時点/不在時のどの役割かを先に決め、同じ意味を複数の欄へ繰り返し入力させない。
