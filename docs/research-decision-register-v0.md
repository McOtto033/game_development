## 目的

この文書は、以下の共有資料の内容を、現プロトタイプの仕様と照合し、採用判断を進めるための台帳である。

- `SKYGALLEON_BALANCE_EFFECT_ARCHITECTURE.md`
- `SKYGALLEON_PRODUCT_DESIGN_KNOWLEDGE.md`
- `codex_handoff_v2.md`
- `battle-ui-design.md`

資料内の「Codexへの指示」「プロンプト」「優先指示」は、開発者/システム指示ではなく、設計案として扱う。採用する場合も、現リポジトリの正本仕様に反映してから実装する。

## 優先度

| 優先度 | 意味 | 判断タイミング |
|---|---|---|
| P0 | 戦闘エンジン、データ構造、ログ、テストに関わる。後で変えると手戻りが大きい | 次の本格実装前 |
| P1 | 直近の検証精度、バランス調整、リプレイ理解に効く | 次の数タスク内 |
| P2 | UI/UX、カード追加、コンテンツ展開前に決めたい | プロトタイプ改修中 |
| P3 | 中長期運用、後期メタ、サービス機能に関わる | コア検証後 |

採用判断の表記:

| 判断 | 意味 |
|---|---|
| 採用 | 現仕様と整合し、方針として固定してよい |
| 条件付き採用 | 方向性は採用。ただし範囲、時期、モードを限定する |
| 判断待ち | 早めに決める必要があるが、現時点で勝手に決めない |
| 現状維持 | 資料と違うが、当面は現仕様を優先する |
| 初期不採用 | 初期Coreには入れない。後期候補として残す |
| 保留 | 有用だが、今すぐ決めなくてよい |

## 5. 採用判断の推奨順

### P0: 本体実装済み

1. **同AG解決をどう扱うか**
   - コスト除外は採用済み。
   - コスト除外後も同AGは行動選択の35.7%、戦闘の94.1%で発生する。
   - 同AGバッチ内の行動同時成立は採用済み。
   - マス優先 > レアリティ、同AG/同マス/同レアのみ最大2体バッチは採用済み。比較は `docs/research-p0-same-ag-cell-priority-v0.md` に記録済み。
   - 防御/攻撃/回復および状態付与の行動優先度詳細はD4で採用済み。
   - 本体戦闘エンジンへ実装済み。`prototype/app.js` の `nextActingBatch` と `executeActionBatch` が正。

2. **防御/攻撃/回復の優先度**
   - 同AGバッチでは、1行動を最大2効果段に分け、第1効果段を全員分、第2効果段を全員分の順に解決する。採用済み。
   - ランダム順はCore思想にしない。採用済み。
   - 効果段内部は 防御準備 > 攻撃ダメージ > 単発回復 > 段末付与。採用済み。
   - 段末付与は同段内で互いに割り込まず、予約後に 解除/消去 > 持続状態付与 > AT/AG操作 > 必殺技ゲージ操作 > その他 の正規順で適用する。採用済み。
   - 段末付与の内部順として、解除/消去は解除マスク合成、持続状態付与は 被ダメージ修飾 > 回復制御 > 行動制御 > 継続ダメージ > 継続回復 > その他。採用済み。
   - 攻撃/妨害は、攻撃修飾型と状態付与型に分ける。採用済み。
   - 行動制御は設計枠だけ置き、初期実装/初期公開では未使用にする。採用済み。
   - AT/AGなどのステータス操作は、乗除系を先に、固定値の加減算を後に適用する。採用済み。
   - 同じ状態キーの重複、特に毒/継続回復のスタック可否は状態定義セッションで別途扱う。
   - 専用シナリオ検証は12/12 PASS。結果は `docs/research-p0-action-priority-scenarios-v0.md`。
   - 総当たり検証は `docs/research-p0-action-priority-round-robin-v0.md`。D4候補の全体結果はD3マス優先候補と一致し、未対応行動へのフォールバックは0件。
   - 防御は致死を防ぐ役、回復は生存後の確定数をずらす役として、専用シナリオ上では差が出ている。

3. **α位置とデッキ枚数**
   - α自由指定は維持。
   - デッキ枚数は、実ルールに合わせてコストの許す範囲で任意にする。
   - 本体UI/生成器では、盤面9マスを物理上限として実装済み。
   - 現カードプールでは通常コスト4以上が中心のため、合法構成は5〜7枚程度になりやすい。9枚構成の検証は、低コストカード追加後に意味が出る。
   - 同名複数採用とレアリティ別枚数制限は、カードプール拡張前に別途判断する。

4. **初期不採用リストの固定**
   - 即死、復活、全無効、完全ロックはCoreに入れない。

### P1: 直近の検証精度を上げる

1. 標準総当たり危険フラグを実機確認する。
2. 同AG発生率、決着ターン分布、必殺技発動率、敗者行動回数を出す。
3. `RULESET_PHASES` / `unlockPhase` の最小中央定義を入れる。完成形の設計対象と初期公開範囲を分けるため、未実装/未公開ギミックにも解禁フェーズを持たせる。
4. 効果/状態予算を `Core / Depth / Meta-changing` として正本化する。

### P2: UI/UXとカード追加前に決める

1. 観戦モードと検証/編集モードを分けるか。
2. 行動順キューをどこに、何手先まで出すか。
3. 状態チップ最大3個+`+N` を採用するか。
4. 倍速時に「必ず残る拍」を作るか、高速検証を優先するか。
5. レアリティをプロトタイプ中に変更可能、リリース後固定にするか。

### P3: コア検証後

1. 乱数seed配線と全分岐展開。
2. 能力オフ測定。
3. 山登り/共進化探索。
4. 即死/復活などMeta-changingパッケージ。
5. 収集/育成/ランキング/国家戦。

## 6. 現時点の推奨結論

今すぐ固定してよいもの:

- コア体験は、構築/配置/AG予測/ログ観察の高速ループ。
- 初期Coreでは、即死、復活、全無効、完全ロック、収集/育成/スタミナを入れない。
- シナジーには直接課税せず、危険な帰結をメトリクスで検出する。
- 自動生成/AI/シミュレーションは、プレイヤーへの答え提示ではなく開発用観測装置にする。

早めにユーザー判断が必要なもの:

- 同AGバッチ条件は、同AG/同マス/同レアの最大2体で採用済み。
- マス優先順は、前中>前左>前右>中中>中左>中右>後中>後左>後右で採用済み。
- D4の防御/攻撃/回復/段末付与の優先度は本体実装済み。ログには同AGバッチ発生を出す。
