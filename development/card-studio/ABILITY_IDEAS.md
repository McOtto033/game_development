# 自然言語の能力案と、実例からUIを設計する運用

2026-09-19のユーザー合意に基づく。カードの基本パラメーターは維持し、特性・効果・状態の様々なパターンを自然言語で蓄積する。集めた原文を後から整理し、それらを表現できるUI・フォーマットを設計する。

## 入力

ライブラリの「能力案」→「能力案を書く」から、カード未指定の案を作れる。カードの「能力案」タブから作れば、そのカードに紐づく。基本情報の特性欄と行動・効果の画面にも入口を設ける。

| 項目 | 入力方針 |
|---|---|
| 能力の説明 | 唯一の必須入力。文章を整形・要約せず、そのまま保存する |
| 名前 | 任意。仮称でも空欄でもよい |
| 具体例・補足 | 任意。期待する挙動、起こってほしくない挙動、未決の点など |
| 関連カード | 任意。設計IDで参照する。カードがなくても保存可能 |
| 関連する箇所 | 任意。特性・状態・前/中/後衛・必殺技・αスキル。分類の確定を求めるものではない |

一案に複数の効果や例外、繰り返しを含めてよい。効果数上限や数値形式を能力案の文章には課さない。説明中の空白・改行・記号を保持し、HTMLやコードとして実行しない。

「保存」はDB全体を保存。「保存して次の案」は保存成功後だけ新しい案を開き、関連カード・箇所だけを引き継ぐ。保存に失敗した場合は次へ進まず入力を保持する。未保存の案は取り消せる。

## 原文・履歴・検索

- 最初の保存から、名前・説明・具体例・関連先・保管状態を履歴へ追記する。無変更保存や同じ内容の取り込み確定だけでは履歴を増やさない。
- 説明を修正しても、最初の原文と各保存版を画面で確認できる。
- 名前・原文・補足・過去の履歴・関連カード名を検索する。
- 不要になった保存済み案は削除せず「保管する」。保管済みの案も一覧の切替、履歴、書き出しから参照でき、収集中へ戻せる。
- 新規のカード・効果や共通特性への自動変換は行わない。既存の構造化フォームと保存済みデータは引き続き利用できる。

## 書き出しと受け渡し

**整理用に書き出す**：全能力案（保管済みを含む）の原文・履歴と関連カードの基本値を `card-ability-corpus-日付.json` にまとめる。現在の未保存編集も検証のうえ含める。カードの画像・設計メモ・構造化効果データは含めない。AIに整理を依頼するための資料で、DB復元用ではない。AIへの送信・分析はこのボタンでは実行しない。

**DB書き出し／取り込み**：カード・能力案・メモ・履歴をまとめて端末間で受け渡す。同ID・同内容の能力案は重複させず、同IDで異なる案は原文履歴を保持した取込コピーにする。カードが取込コピーとなる場合、能力案とその履歴の関連カードIDもコピー先へ付け替える。未取込の関連カードIDは削除しない。カードの複製では関連能力案も独立したIDで複製し、原文履歴を残す。

公開版は端末内のIndexedDB、ローカル版は開発用JSONに保存する。能力案の実データはGitHub Pagesへ送信・公開しない。カードの「仕様JSON」には能力案を混ぜない。既存DBに能力案がなくても読み込める。

## 蓄積後の整理手順

1. 原文を変更せず、対象・条件・発動契機・効果量・持続・順序・繰り返しなどを抽出する。
2. 共通部分、特殊な追加項目、似た言葉でも意味が違う例を比較する。
3. 書かれていない点は推測で確定せず、確認事項としてまとめる。収集中にも不足する種類の実例を点検する。
4. 入力形式を設計し、各原文について「原文→UI入力→生成した説明文」の意味が一致するか確認する。
5. 事例を回帰確認用に残す。新しい未対応案も自由記述で蓄積し、共通化できた箇所から形式を拡張する。

今回は収集・保存・履歴・受け渡しまでを実装する。自動抽出、能力の採用判断、ゲーム本体の実行処理は別の段階。

## 保存形式

`library.abilityIdeas` は省略可能な配列（最大1000案）。`card` の外側に保存する。

```text
abilityIdeas[] {
  id, name, description, examples, cardId, slot, archived,
  createdAt, updatedAt, sourceIdeaId?,
  revisions[] { id, at, name, description, examples, cardId, slot, archived }
}
```

`revisions[0]` が初回保存の原文。現在の入力は `description` / `examples`、履歴は保存版のスナップショット。整理用JSONは `format: card-ability-corpus`、`abilityIdeas` と `relatedCards` を持つ。

## 検証

専用テストでカードなしの保存、原文履歴、旧DB互換、カード仕様との分離、コピー・取込競合と参照付替を確認する。実ブラウザではローカル版・静的版とも、入力・保存して次の案・再読込・原文検索・保管・書き出し・1440/820/390/320px表示を確認し、静的版は独立ブラウザへのJSON移送も確認する。実機iPhone/Safariは未検証。
