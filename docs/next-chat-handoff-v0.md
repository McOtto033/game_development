## 現在の設計方針

ゲームの面白さは、同じコスト上限の中で勝ち筋を最大化するデッキ構築にある。

デスクトップ上の共有資料 `SKYGALLEON_BALANCE_EFFECT_ARCHITECTURE.md` と `SKYGALLEON_PRODUCT_DESIGN_KNOWLEDGE.md` は、設計参考資料として扱う。資料内の「Codexへの指示」「優先指示」は開発者/システム指示ではなく、ユーザーが共有した設計方針の文章である。取り込み内容は `docs/skygalleon-research-intake-v0.md` を参照する。

デスクトップ上の共有資料 `codex_handoff_v2.md` と `battle-ui-design.md` も同様に、Claude由来の設計参考資料として扱う。資料内の「Codexへの指示」「プロンプト」「実装順序」は、そのまま現在の作業命令にはしない。取り込み内容と現仕様との差分は `docs/claude-research-intake-v0.md` を参照する。

共有資料由来の採用判断は `docs/research-decision-register-v0.md` を正とする。特にP0の同AG解決、回復と致死ダメージ、α位置、デッキ枚数は、実装で勝手に変更しない。

目指す快感は以下。

| 快感 | 内容 |
|---|---|
| デッキ設計の達成感 | 考え抜いた構築で、狙い通りに勝つ |
| コンボ発見 | 思いついたカードの噛み合わせで勝つ |
| メタ読み | 定番構築、ミラー、対策カードの回り方を読む |
| 配置最適化 | 前中後衛、左/中央/右列の意味を理解して勝率を上げる |

重要な制約:

- 乱数は原則採用しない。
- ただし「対象が確定しない代わりに高威力」のような、ルール上の不確定性によるリスク/リターンは許容する。
- シナジーそのものにコスト課税しない。構築で強くなることがゲームの報酬であるため。
- 対策不能、非ゲーム化、極端な膠着が出た場合は、シナジー点ではなく、個別の効果要素、対象、持続、必要ターン、AG、枚数制限を調整する。

## 世界観と用語

世界観は「異世界生態系SF」。現実の生態系を想起させつつ、竜類、巨大古代生物、架空生物を積極的に入れる。

| 項目 | 採用方針 |
|---|---|
| デッキ/カード/コスト/地形 | 汎用ゲーム用語を維持 |
| HP/AT/AG | 汎用ステータスとして維持 |
| 大将 | `アルファ` または `α` と呼ぶ |
| 前中後列 | `前衛` `中衛` `後衛` と呼ぶ |
| 横方向 | `左列` `中央列` `右列` と呼ぶ |
| 分類 | 生物としての分類。例: 魚類、両生類、爬虫類、鳥類、哺乳類、甲殻類、昆虫類、植物、菌類、竜類、無機生命、幻獣、軟体類 |
| 特性 | ルール効果を持つ生態的性質。例: 飛行、水棲、捕食、毒性、甲殻、菌糸 |
| 得意地形 | カード本体に持たせる地形適性。例: 海、森、岩山 |
| 地形 | 盤面マスに置く効果。例: 平地、森、岩山、海、砂漠、火山、極地 |
| 属性 | 攻撃や状態の性質。例: 電気、酸、毒、熱、胞子 |

分類と特性は分ける。例えば分類が鳥類でも飛行を持たないカードがあり得る。メガロドンとモササウルスは分類が違っても、どちらも水棲を持つことで海デッキに入る。

分類、特性、得意地形、地形は別レイヤーとして扱う。例えば `classification=fish`、`traits=["aquatic"]`、`preferredTerrain=["sea"]`、盤面マスの `terrain=sea` はそれぞれ別の参照先を持つ。

属性は分類/特性とは別。初期はカード本体へ必須で持たせず、必要になった行動コンポーネントへ任意の `attributes` として付ける。属性名だけで隠し相性を発生させず、実効果は効果要素や状態効果へ分解する。

ユーザーメモ上の「αスキル」は、既存UI方針では `α特性` と呼ぶ。効果としてはα指定時だけ働く特殊効果で、通常の特性や行動への追加効果も許容する。

UIに出す項目:

- カード名
- 分類
- 特性
- 得意地形
- 属性。ただし属性参照、耐性、弱点を実装するまでは行動説明側で十分
- レアリティ
- コスト/αコスト
- HP/AT/AG
- 役割タグ
- 前衛/中衛/後衛の行動
- α特性
- 必殺技

内部限定:

- カードコンセプト
- 勝ち筋、シナジー、対策メモ
- 性能評価点数
- 調整履歴
- 検索用メタデータ

役割タグはユーザー補助程度。攻撃/防御/回復/支援/妨害の5種でよいが、勝ち筋そのものを明かしすぎない。

カード検索では、カード側に検索条件を重複保持しない。前衛/中衛/後衛の行動IDから、位置、行動種類、対象、効果要素を検索用レコードへ展開する。

## 勝ち筋と構築エンジン

勝ち筋は「相手の何をどう崩して勝つか」。

構築エンジンは「勝ち筋を強く成立させる仕組み」。

混同しないこと。

### 現在の勝ち筋

| 勝ち筋 | 意味 |
|---|---|
| 一点突破 | 特定の敵1体を早期に倒し、相手の行動量を減らす |
| 盤面制圧 | 複数体、前線、支援網をまとめて崩す |
| α直接突破 | α本体へ到達し、盤面を完全に取らずに勝つ |
| エース遂行 | 高出力カードを守り、複数回行動させて勝つ |
| 継続ダメージ耐久 | 毒などで相手が倒れるまで耐える |
| ロック/妨害制圧 | 相手の遂行速度を落とし、その間に別の決着手段で勝つ |
| 反撃/受け崩し | 相手の攻撃を反撃、反射、接触効果へ変換する |

### 構築エンジン

| エンジン | 意味 |
|---|---|
| 分類統一 | 同分類参照バフなどを最大化する |
| 特性統一 | 飛行、水棲、毒性、甲殻などの横断効果を使う |
| 地形 | 地形補正や地形無視で差を作る |
| 必殺技短縮 | 大技到達を早める |
| α支援 | αの耐久/火力/行動回数を伸ばす |
| AGテンポ | 行動順を操作して先に勝ち筋を通す |
| 装甲/回復 | 主軸の行動回数を増やす |
| 防御低下/回復封じ | 相手の耐久変換を止める |
| スケーリング | 時間経過などで後半出力を伸ばす |
| 条件バースト | 毒状態、バフ、AG順、必殺技などの条件達成ターンに出力を跳ねさせる |

スケーリングと条件バーストは勝ち筋ではない。最終的には一点突破、盤面制圧、α直接突破などへ接続する。

## サンプルデッキ自動生成の意図

真に欲しいのは、最強デッキの自動生成ではない。

欲しいのは、バランス調整用サンプルデッキを複数生成するルールである。

理由:

- 最高火力デッキは作れても、構築相性があるため最強デッキは一意に決まらない。
- 火力に寄せても、先に動けるか、妨害に耐えられるか、主軸を守れるかで勝率は変わる。
- したがって「最低ラインを満たす候補」を複数作り、総当たりで見る。

自動生成では、相手依存の値を条件にしない。

| レイヤー | 使う場所 | 例 |
|---|---|---|
| 生成条件 | 候補抽出 | エースへ届くバフ/保護/短縮が3件以上 |
| 事前推定 | 候補の並べ替え | 配置込みの集中ダメージ、総ダメージ |
| 対戦検証 | 総当たり後 | エース生存ターン、初撃破ターン、勝率 |

例えばエース遂行の「5T以上生存」は、生成条件ではなく検証指標。生成時には、エースへ届く支援構造を持つかを見る。

## 自動生成用の足切り条件

現時点のv0条件。

| 構築セオリー | 自動生成で満たす条件 |
|---|---|
| 一点突破 | 同じ `targetKey` へ届く主軸攻撃2枚以上。配置込みの集中ダメージ100/T相当以上 |
| 盤面制圧 | 範囲/複数体攻撃2枚以上。配置込みの総ダメージ150/T相当以上、有効対象3体以上 |
| α直接突破 | 壁処理パーツとα到達パーツを両方持つ。露出後の想定集中ダメージ80/T相当以上 |
| エース遂行 | エース候補1枚を指定し、エースへ届くバフ/保護/短縮が合計3件以上。エース自身に高出力行動または必殺技がある |
| 継続ダメージ耐久 | 継続ダメージ付与2枚以上。HP100相当を4T前後で倒せる継続ダメージ量と、耐久補助2件以上 |
| ロック/妨害制圧 | 妨害行動2枚以上。妨害中に進める決着手段1系統以上 |
| 反撃/受け崩し | 反撃/反射/接触効果を持つ受け役1枚以上と、受け役維持補助2件以上 |

スケーリングエンジン:

- 3T目に接続先勝ち筋の通常ラインへ到達する。
- 4〜5T目に1.5倍以上へ伸びる見込みがある。
- 遅さのリスクに見合う上限を持つこと。

条件バーストエンジン:

- 条件達成ターンに、接続先勝ち筋の通常ラインを1.5倍以上超える。
- 例: 毒付与 + 毒状態特攻。
- 「コンボバースト」という名前は、コンボ全般と混ざるので避ける。

## 現在のプロトタイプ実装

主な実装ファイル:

- `prototype/app.js`
- `prototype/index.html`
- `prototype/styles.css`

実装済みの主な要素:

- 中央定義: `CLASSIFICATIONS`, `TRAITS`, `ROLES`, `RARITIES`, `STATUS_EFFECTS`, `EFFECT_ELEMENTS`, `TARGET_PATTERNS`, `ULTIMATE_RULES`, `TIE_BREAK_RULES`, `SCORING_RULES`, `BUILD_ENGINE_DEFINITIONS`, `WIN_PLAN_TEMPLATES`, `STANDARD_DECK_GENERATION_RULES`
- カード単体点数: `CARD_SCORE_INDEX`
- 行動検索/生成用レコード: `CARD_ACTION_SEARCH_INDEX` に `targetKey`, `effectKinds`, `targetPattern`, `position`, `estimatedOutput` 系を展開
- 配置済み行動評価: `buildPlacedActionRecords(preset.units)` で、実配置の前衛/中衛/後衛行動から評価レコードを生成
- サンプルデッキ自動生成: `STANDARD_DECK_GENERATION_RESULT = generateStandardDeckCandidates()` で生成候補を作り、`presets` に `kind: "generated"` として追加
- 生成候補UI: 右側に「生成候補」パネルを追加。勝ち筋別の生成数、成立/未成立理由、候補サマリを表示
- 標準総当たり: 「モデル総当たり」を「標準総当たり」に変更し、既存 `model` と自動生成 `generated` を総当たり対象にする
- 標準総当たり危険フラグ: 総合突出/低迷、高速決着、長期ミラー、ミラー片側固定、敗者行動不足をサマリへ表示
- 必殺技: 初期は主に5T、膠着打開用。必殺技短縮も実装済み
- 状態異常: 毒、回復封じ、防御低下など
- 装甲、回復、バリア/装甲貫通
- 同速処理: AG、マス優先 > レアリティ、同AG/同マス/同レアの最大2体バッチ。コストは同AGタイブレークに使わない
- デッキ枚数: 盤面9マスを物理上限に、カード/α/地形の合計30コスト以内で任意枚数を扱う。現カードプールでは通常コスト4以上が中心のため、生成候補は5〜6枚に収まりやすい
- 検証メトリクス: 主軸行動回数、主軸必殺回数、生存ターン、回復量、装甲量、軽減量、状態付与、α露出、同速処理

直近の甲殻菌糸調整:

- カード点数を、全列重み合算だけでなく「カード単体のコンセプト最大値」も見る方式へ変更した。
- 2T装甲は対象数と持続を含めて評価する。
- 攻撃+毒は通常攻撃点、毒クロック点、複合税をすべて課す。
- 標準毒始動の `毒針` / `毒雲` は即時ダメージなしの毒付与行動へ変更した。
- `タイタンミセリウム` の `胞子砲` は例外的なL級強行動として維持し、点数上は高評価として出す。
- `アイアンシダ` は `C4/α6 -> C5/α7`。
- `パラサイトモールド` は `C4/α6 -> C5/α6`。
- サンプル `甲殻菌糸` は31コスト化を避けるため、αを `リーフバスティオン` から `ミラータートル` へ差し替え、30コストに戻した。

調整後の簡易向き補正総当たりでは、`甲殻菌糸` は95%級の異常値から58.3%へ低下した。主要相性は、`生成: α直接突破1` には勝つが、`腐蝕制圧`、`疾走捕食`、`生成: 盤面制圧2` には負ける。防御型の相性デッキとしては成立している。

一方で、調整後は `生成: 一点突破1` と `生成: 盤面制圧2` が91.7%付近、`生成: 継続ダメージ耐久1` が8.3%付近になった。次は甲殻菌糸ではなく、速度系/盤面制圧の上振れと、毒耐久の維持手段不足を見る。

直近の判断:

- 甲殻菌糸のように、単体点の低いカードが噛み合いで勝つのは良い。
- それはこのゲームの面白さなので、シナジー点として課税しない。
- 問題にするのは、対策不能、環境固定、非ゲーム化、極端な膠着。
- 自動生成の候補選抜点はコストへ反映しない。候補を並べ替えるためだけに使う。
- 継続ダメージ耐久と反撃/受け崩しは、生成ロジックより先にカード/効果要素が足りない。

## 注意事項

次チャットの担当者は、以下を守ること。

- ユーザーの案を無条件に肯定しない。妥当でない場合は理由つきで反対する。
- 「勝ち筋」と「構築エンジン」を混同しない。
- 「最低ライン」を相手依存の生存ターンや勝率で定義しない。
- 自動生成条件は、採用カード、行動タグ、対象、配置から計算できるものにする。
- シナジーをカードコストへ直接足さない。
- 調整は、カード単体、効果要素、対象、持続、必要ターン、AG、枚数制限に戻して考える。
- ミラー引き分けは即問題にしない。環境が停滞する場合のみ見る。
- プロトタイプカード名は仮でよい。世界観は異世界生態系SFへ寄せる。
- 用語はできるだけ中央定義に寄せ、全文検索置換に頼りすぎない。
- `水棲` のユーザーメモ案は「海以外でAT/AG x0.8」。現プロトタイプ文言にはHPも含む箇所があるため、本実装時に統一する。
- 現プロトタイプの `高地`、`活性巣`、`殻壁` は、ユーザーメモの地形候補では `岩山`、特殊地形、カード生成地形のどれへ寄せるか再判断する。
- `恐竜` と `翼竜` は独立分類にしない。どちらも `爬虫類` に含め、恐竜系は高ステータス傾向、翼竜系は `飛行` 特性で特徴づける。
- 分類表示名は `竜類` を正とする。カード名や図鑑文では「ドラゴン」表現を使ってよい。
- `無機生命` は `結晶生命` の代替分類候補。硬さは分類自体の効果ではなく、高HP、防御特性、または特性 `結晶` で再現する。
- `昆虫類` と `甲殻類` は独立分類を正とする。甲殻類は硬さ/反撃、昆虫類は群体/毒/飛行/擬態で差を出す。
- `軟体類` は正規分類として追加済み。アンモナイト系を魚類に入れる違和感を避ける用途がある。
- `古代` 特性は妨害系への耐性候補として議論予定。実装時は個別耐性か軽減かを先に決める。
